# 知行后端

全仓产品矩阵、H5/小程序功能、后台菜单及操作发布流程见[操作指引](../docs/PROJECT_OPERATIONS_MANUAL.md)。

轻量级 **FastAPI + SQLite + APScheduler** 架构，支持数据持久化、定时爬取、管理后台 RBAC。

## 架构选型

| 组件 | 选型 | 说明 |
|------|------|------|
| Web 框架 | FastAPI | 轻量、异步、自带 Swagger |
| 数据库 | SQLite (WAL) | 零配置持久化，可换 PostgreSQL |
| ORM | SQLAlchemy 2.0 | 类型安全 |
| 认证 | JWT + RBAC | 管理端角色权限 |
| 定时任务 | APScheduler | 每日自动爬取文章 |
| 爬虫 | httpx + 可扩展 | 当前内置模拟源，可接 RSS/真实站点 |

### 已退役历史说明：人民日报评论文章

管理端「人民日报 → 评论文章」复用全量电子报和客户端文章档案，先识别评论版及明确栏目名（如人民时评、今日谈、人民观点、金台随笔、和音、社论、微观等），再接收全量文章 AI 全文评估中高置信识别出的评论/社论稿。原文 Markdown/HTML 可预览；服务端 LLM 已启用时自动生成待审三刀解剖草稿（最多 2 篇并发），未启用时可逐篇手动提交。所有解剖稿都需人工编辑审核，通过后才标记为可用。文件存放在持久化数据目录 `server/data/rmrb/comments/`；不配置服务端 LLM 时，规则命中的原文归档仍可用。

管理端「人民日报 → 客户端评论 / 金句」单独采集客户端评论页最近 48 小时文章（以页面 `publishTime` 为准），列表支持分页，支持与电子报重复稿去重，并复用评论文章原文/三刀流程。审核顺序为先确认文章是否属于评论文章，再审核金句；排除文章会删除其金句。标题含明确栏目/系列前缀时，排除操作会建立同前缀自动过滤规则，并过滤当前及后续匹配文章；没有稳定前缀时仅排除本篇。金句采集优先读取来源网页的加粗标记，将标记对应到档案正文中的完整原句；无加粗标记时先按完整句切分，再由 AI 筛选所有符合申论迁移要求的候选句，保存时使用原文句子编号回填，避免模型截句或改写。候选保留来源类型，默认待人工审核；选择「不采用」会删除该金句。主题、适用场景和仿写示例由 AI 补充或人工完善。金句记录存于 `rmrb_comment_quotes`，排除规则存于 `rmrb_comment_exclusion_rules`。

管理端「人民日报 → 金句运营库」统一呈现已审核通过的金句，运营人员可按主题/关键词筛选，选择金句后建立每日运营包，生成并编辑小红书与公众号初稿，预览/导出中国红品牌 HTML 与纯文案。文案由规则模板生成，必须人工检查后发布；系统不连接外部平台发布接口。点击对应平台「标记已发布」后，该运营包金句计为已使用并从默认未使用池隐藏，防止重复运营；草稿不占用。运营包存于 `rmrb_quote_ops_packages`，金句关联存于 `rmrb_quote_ops_package_items`。

「人民日报 → 金句管理」是独立金句总库页面，分页展示全部已审核采用的评论金句，支持全文/来源文章搜索、主题与使用状态筛选，并显示出处、适用场景、仿写和已发布运营包记录。运营包制作与平台文案编辑仍在「金句运营库」完成。

### 已退役历史说明：人民日报全量文章 AI 评估

管理端「人民日报 → 全量文章」支持逐篇/批量全文评估、按评估状态筛选和查看报告；全量采集完成后会自动排队。需配置服务端 `LLM_ENABLED=true` 与 `LLM_API_KEY` 才会调用模型；未配置时记录保留为待评估。报告分别判断文章体裁和评论/观点属性，并包括申论关联、主题、适用场景、摘要、观点、结构、六项评分、原文证据和物料建议。评分按主题价值 20%、可迁移性 25%、事实素材 20%、表达质量 15%、论证结构 10%、时效性 10%折算。高/中关联文章保存正文文件版本，低关联正文仅用于本次评估并保留正文哈希与报告。AI 建议不直接覆盖最终分类；人工确认时核验原文证据，无法定位的证据会阻止确认。全文模型识别为评论/观点稿的文章可同步进入评论物料流程。评估结果存于 `rmrb_article_evaluations`，正文仍以档案文件版本存储，不放入 SQLite 正文列。

## 每日金句库（2026-10-13已部署）

后台只保留“人民日报 → 金句管理”。支持独立录入、编辑证据与多个主题仿写、日期筛选、JSON预检导入/去重/导出、确认与精选。LLM整理结果为待核对；采集正文仅在共享池保留48小时，正式金句库只保存逐句证据摘录及来源，模型遥测不保存提示词或原始响应。

配置（server/.env，不要提交密钥）：
- `DAILY_QUOTES_ENABLED=true`：启动独立定时任务；false只关闭自动运行。
- `DAILY_QUOTES_PEOPLEAPP_FALLBACK_ENABLED=true`：纸版当天入库不足时，启用人民日报客户端评论页近24小时兜底；客户端正文仅内存临时处理，不进入全量文章档案。
- `DAILY_QUOTES_MIN_QUOTES_BEFORE_FALLBACK=3`：低于该句数时触发客户端兜底，设为0可关闭数量触发。
- `DAILY_QUOTES_HOUR=7`、`DAILY_QUOTES_MINUTE=10`：北京时间；优先等待词汇联合分析复用结果，但最多等到08:30后独立启动；失败/部分完成任务自动重试至10:00。若生产环境显式配置旧调度值，部署时同步调整词汇先于金句。
- `LLM_ENABLED=true`、`LLM_API_KEY`、`LLM_BASE_URL`、`LLM_MODEL`：复用服务端配置；未配置时页面提示，不伪报整理成功。DeepSeek 当前推荐模型名为`deepseek-flash`（服务版本 V4.1-Flash-1017）；旧名`deepseek-v4-flash`仍兼容并路由到同一服务版本。
- 任务状态：queued/running/completed/partial/failed/empty；数据库防重，同日成功文章跳过，部分失败可重试。后台权限rmrb:read / rmrb:write。

旧采集与AI评估调度不再启动；旧/admin/rmrb-archive、/rmrb-comments、/rmrb-quotes接口已撤销，不能通过旧直链触发。学员端/api/rmrb与时评精拆不属于退役范围。

### 每日金句规则与流程优化（2026-10-18，本地实现，待部署）

- 全报非广告版面先发现目录：明确评论栏目直接纳入，补齐和音、金台锐评、四海听音、环球走笔等；未知栏目以20条一批分类，不确定文章通读正文后再判断。目录分类响应不合法时停止并报安全错误码，不伪报完成。
- 默认范围为评论、时评和观点手记。`DAILY_QUOTES_INCLUDE_EXTENDED=false`；设为true可纳入专家点评、专题深思、理论、建言、提案及文艺创作评论扩展池。目录保存标题、URL、版次及纳入/排除分类，正文仍只在内存临时处理。
- 先比较候选再精选最多3句，12—55字优先，70字硬上限；连续节选不改原文。模型自评记忆成本、逻辑、迁移、亮点四项至少各3/5且总分至少16/20。自评分只作筛选提示，不代表质量认证，仍须人工审核。
- 候选初筛只生成原句、主题、结构和质量说明，不生成作文仿写。审核通过并启用后可点击“生成仿写”，进入当天运营精选时也会自动补充两个不同主题的80—150字示例；重复精选时跳过已有仿写。
- 原句连续性、长度、低分及领导人引语拒绝仍严格执行；引语校验定位到引述范围，不再因证据邻文出现领导人姓名直接拒绝。自动检测不是引语归属的完整证明，审核时仍需核对。
- 高亮不在对应正文中时移除并记录警告，保持正文原样；不对错字原句作模糊匹配。单条写入用savepoint隔离，一句失败不再丢掉整篇。两种构件改为质量提醒，不通过改标签凑构件。
- 有失败的文章保留partial供重试，合格句已入待审；按来源与原句指纹去重，已有人工审核和启用结果不覆盖。已完成文章仍跳过，本次规则升级不会重写既有采集记录。
- 金句、词汇和申论素材共用人民日报版面目录及48小时正文/联合分析缓存；词汇任务默认06:40按批次一次分析并输出三类候选，金句任务默认07:10等待批次结束后复用结果，缺失或旧规则版本项才单独补分析。申论候选须通过原文证据、闭集类型、8/10质量门后进入待审核；人工确认前不可采用或发布。任务重试复用同刊期、同正文指纹的完整分析，避免重复发送全文。金句任务最迟等待至10:00；显式生产调度值需按先联合分析后金句同步调整。缓存目录元数据保留7天。
- `LlmUsageLog`只记录用途、模型、调用状态、token及耗时，不保存提示词、原文或模型输出；后台“大模型用量”按北京时间统计，输入/输出每百万token价格可从环境变量配置。申论素材当前只做结构化人工录入与规则校验，不使用大模型。
- 任务元数据包含ruleVersion、directory、失败stage/code/index和警告计数；不保存全文、完整提示词或模型原始响应。保持rmrb:read/write权限。
- 当天纸版入库不足3句时，按北京时间补采人民日报客户端评论页最近24小时目录，逐篇临时抓取正文并复用同一套引语、连续性、长度和质量校验；来源链接、发布日期和必要证据随金句入库，客户端全文不进入文章档案。历史刊期重跑不混入最近24小时客户端文章。
- 若词汇任务未出现或仍在运行，金句自动任务最多等待至08:30，之后自行入队；任务状态附带纸版/客户端发现数、正文处理数、候选数、质量拒绝数、重复数、入库数及零结果原因，后台页面轮询展示。

### 人民日报词汇素材（本地实现）

管理端“人民日报 → 词汇素材”提供按刊期自动/手动采集当天纸版全版文章、按正文去重、AI联合提取金句/成语/固定表达/重点词语/申论素材、原文证据硬校验和批次统计。金句、词汇与申论素材分别存储和审核；申论候选需质量分至少8且无否决项，进入独立“申论素材”页面待审核，案例/语录必须通过专属核验。编辑后重新进入待审核。数据库新增`rmrb_vocabulary`和`rmrb_vocabulary_jobs`，首批词汇/申论种子随启动幂等导入。默认北京时间06:40自动联合采集（`RMRB_VOCABULARY_ENABLED`、`RMRB_VOCABULARY_HOUR`、`RMRB_VOCABULARY_MINUTE`可配置），每15分钟检查并最多重试4次；不向学员端发布。

### 人民日报申论题型每日练习生成（本地实现）

- 每日09:00—11:00检查前置任务：LLM 已启用、当天共享采集池可用，且词汇联合分析任务已完成或部分完成。出题复用`RmrbDailyPoolArticle`短期正文缓存与同批联合分析结果，不启动已经退役的全量档案采集/评估任务。
- 按`server/app/knowledge/shenlun_exam_standards.json`中的2020—2025国考/教材题型规则、给定资料DNA和题型自查标准筛选候选；生成与复核还参考`server/app/knowledge/shenlun_benchmark_cases.json`中的8个教材真题任务结构样例，并在每题质量报告中记录基准集版本。除材料质量分≥8和证据可回查外，必须有公共议题、治理或政策执行类材料锚点，正文指纹去重后每批最多处理3篇、每篇至多生成2题。逐项检查摘录连续性（拒绝省略标记）、逐点答案证据、答案对每个要点的覆盖引文、题干任务、至少3条题型评分维度、参考答案与不少于160字的教学解析。常规题优先4—6个归并要点，最多8个；超出常规数量须说明独立性并通过颗粒度复核。明确答案字数上限由代码硬校验。硬规则通过后，每篇最多再调用一次同一服务端LLM作结构化语义复核；材料外事实/名称、证据过度推断、答案漏点、任务不匹配等实质问题即使被模型标成一般也不能入库，缺少或无法定位复核引文同样退回。复核还须按题型历年真题任务结构基准复核设问，并逐点说明材料证据如何支持要点、答案如何保留要点对象与动作；理由缺失或空泛即退回，并在后台展示供教研核验。评分仅作辅助，不能抵消硬性问题。后台记录逐篇处理进度；旧规则草稿显示为需复核。人工审核的结论、问题维度、意见及修改标记写入质量报告并保留最近50条审核变更历史，便于后续整理校准样本；`GET /admin/shenlun-exercises/review-metrics`提供审核结论、题型和高频问题维度汇总，`GET /admin/shenlun-exercises/review-dataset`支持筛选、分页导出带审核时题目快照的完整 JSON 样本；教研反馈统计按生成规则版本聚合审核结论与修改数。模型复核仍不等于教研审核。
- 规则分低于8/10、关键维度不达标或命中硬错误的结果只记为质量退回；模型调用与处理异常单独记录为运行失败。无合格练习但筛选已正常完成时标为“已完成”，系统异常且无草稿时标为“失败”。历史版本草稿需按当前规则复核。
- 生成内容保存为`ShenlunExercise`草稿，绝不自动发布。后台“申论练习”分为“题目管理 / 自动出题 / 教研反馈”三个 Tab；自动出题页展示批次进度、候选总数与本批处理数、质量分、质量退回、运行失败和材料去重结果；同刊期再次发起会续跑之前未处理的候选，失败文章保留重试机会；教研审核后才可发布。学员提交后查看材料证据、参考要点、示例答案、解析，并订正复盘；不自动评分。
- `RMRB_SHENLUN_AUTO_ENABLED=true`默认开启，设为`false`关闭；管理端可以对某刊期手动补跑。上游联合分析失败时可从申论练习页直达“词汇素材”并预填刊期，手动重跑。自动任务达到上游重试上限后不会因LLM余额恢复而自动复位。`shenlun_exercise_jobs`和练习质量审计字段随服务启动自动创建/补列。每日任务要求服务端 LLM 配置正确；变更该功能的调度/标准后应先在本地观察批次，再按本机部署流程发布。
- 管理端审核反馈可按题型分页导出完整的题目版本快照 JSON；使用`python3 server/scripts/analyze_shenlun_review_dataset.py <样本.json>`可生成按生成规则版本、题型、审核结论和问题维度汇总的 Markdown 复盘报告。导出格式带`schema_version`与北京时间`exported_at`，少于10条的规则版本样本仅作线索。
