## 发布完整性约束

- 内置科目的 `tree_key` 是稳定身份，结构化草稿标题必须与科目对应（例如 `资料分析` 只能发布标题为「资料分析」的树）。
- 保存草稿、导入 Markdown、固化版本、激活版本和修改科目名称均在服务端校验；不能把一棵结构有效但属于其他科目的树发布到当前键。
- 新建或维护扩展科目时，显示标题可以自定义；内置科目不可改名。发生跨科目误导入时，发布和激活门禁会拒绝该版本。
- 恢复操作应先备份生产数据库，再从 `knowledge_tree_versions` 选择经过核验的正确快照；不要用整表删除重建来恢复。
