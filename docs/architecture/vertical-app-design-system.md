# 垂直题型应用统一设计与工程规范

## 1. 核心原则

知行公考采用“统一体验、独立产品、共享契约”的多应用模式。

- **统一体验**：所有题型应用使用同一信息层级、空间尺度、卡片样式、交互反馈与四栏导航结构。
- **独立产品**：每个题型拥有独立源码、路由、状态、构建、AppID、域名与发布节奏，不再通过构建变量切换。
- **共享契约**：后端 API、内容模型、埋点协议和设计规范可以共享；前端运行时代码不跨应用引用。
- **简单又深入**：首页只呈现“今天学什么”，深度能力进入专题、训练和复习链路，避免把所有功能堆在首屏。

### 1.1 共性功能必须与综合版完全一致

`src/` 综合应用是共性功能的产品基准。申论、政治理论以及后续题型应用中，凡是已经存在于综合版的功能，不允许实现为精简版、相似版或仅保留入口，必须同时满足：

- 页面信息结构、字段、文案语义、按钮状态和操作顺序一致；产品名称等领域文案可以替换。
- 使用相同后端接口、请求字段、身份状态、业务校验和错误处理。
- 加载、空态、失败、权限、确认、成功反馈和中断恢复行为一致。
- H5 与微信小程序上的导航结果、触控尺度和视觉层级一致。
- 综合版共性功能发生变更时，两个垂直应用必须在同一里程碑同步并通过回归检查。

学科专属的首页、内容、训练方法、评价规则和学习资产可以不同；是否属于学科专属不能以“开发更快”为判断依据。

## 2. 统一页面骨架

每个题型产品固定四个一级入口：

1. **今日**：连续学习入口，包含进度、今日主任务、建议时长和继续学习按钮。
2. **学习**：该题型的知识与方法体系。名称可按领域改为“精读”“专题”等。
3. **训练**：真题化练习、结果解析、错题复习。名称可显示为“刷题”。
4. **我的**：学习数据、收藏、历史、设置和反馈。

首屏信息顺序固定为：轻量问候与连续天数 → 品牌主卡 → 今日路径 → 最近学习/内容推荐。每屏只保留一个主操作。

## 3. 视觉语言

- 画布宽度按 375px 设计，页面水平留白 16px。
- 页面背景使用柔和灰，内容卡使用白色；卡片圆角 14px，区块间距 12px。
- 正文主色为近黑，次级文字为中灰，弱提示为浅灰；颜色只能来自项目内 `styles/variables.scss`。
- 品牌主卡统一使用克制的中国红深色渐变；产品差异由名称、内容和领域图形表达，结构、尺寸、颜色和动效保持一致。
- 四栏导航统一使用 81×81 透明 PNG 线性图标：未选中为中性灰、选中为中国红，依次对应日历任务、知识书本、答题文件和个人档案。
- 标题优先使用 20/17/15px 三档，正文 14px，辅助信息 12px；避免过多字号与字重。
- 按钮与可点击区域最小 44px；操作后立即反馈，加载、空态、错误态保持相同语气。

## 4. 交互标准

- 用户打开应用后一步即可继续今日任务。
- 学习路径保持“输入内容 → 方法拆解 → 主动练习 → 反馈复习”的连续闭环。
- 返回后保留阅读/答题位置；中断任务可继续；完成后明确推荐下一步。
- 一级导航稳定，不因运营活动或内容变化改变位置。
- H5 与微信小程序共用信息架构，平台差异只在导航与系统能力适配层处理。

## 5. 工程边界

每个 `apps/<product>-app/` 至少包含：

```text
config/                 独立构建配置与端口
src/app.ts              独立应用入口
src/app.config.ts       独立路由与 TabBar
src/components/         产品内组件
src/pages/              产品内页面
src/styles/             产品内设计 token
src/api/                共享后端契约的产品适配层
package.json            独立命令与依赖声明
project.config.json     独立小程序工程配置
```

禁止从另一个应用的 `src/` 直接 import。公共能力先形成稳定接口契约，再由各应用自行实现或通过版本化基础包升级；不得用产品判断分支隐藏页面。

## 6. 后续题型接入检查表

- 独立目录、端口、产物目录和小程序工程配置。
- 四个一级入口符合统一骨架。
- 颜色、间距、圆角、阴影、触控区域通过设计 token 实现。
- 首页只有一个主任务，深层功能按学习闭环组织。
- API、事件和内容字段符合共同契约。
- 登录、注册、个人资料、头像、改密、签到、积分、反馈、数据管理和通用设置逐项对照综合版，不得降级。
- H5 与微信小程序均构建通过，再进入业务功能迁移。
