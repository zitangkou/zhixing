# 原综合版页面与功能迁移基线

> 基准应用：仓库根目录 `src/`。本清单是申论、政治理论及后续垂直应用迁移的唯一功能基准。
> 更新规则：原版共性功能变化时，必须同步更新本清单和已发布垂直应用。

## 1. 一致性判定

相同功能只有同时满足以下六项才算完成迁移：

1. **页面结构**：区块、字段、信息层级、主次操作和导航结果一致。
2. **业务字段**：请求、响应、草稿和持久化字段不降级、不合并丢失。
3. **接口契约**：使用相同后端接口、鉴权、产品上下文和错误码语义。
4. **操作逻辑**：校验、保存、编辑、删除、确认、恢复和完成条件一致。
5. **反馈状态**：加载、空态、失败、禁用、成功、登录失效和弱网恢复一致。
6. **双端表现**：H5 与微信小程序均可完成同一流程，视觉尺度和触控结果一致。

产品名称、领域文案、题型内容和学科专属评价规则允许不同。不能以“垂直应用更简单”为理由删除原版已有能力。

## 3. 申论完整迁移契约

### 3.1 时评详情

- 保留来源、日期、标签、可选择正文、手写提示。
- 保留复制全文、记入语料和三刀解剖三个操作。
- 从每日任务进入时，先保存 `articleId`、`readCompleted` 和第 1 步进度。
- 普通阅读入口与每日任务入口都进入同一详情页，不复制第二套页面逻辑。

### 3.2 三刀解剖

页面以原版 `pages/rmrb/mine-edit` 为准，必须完整迁移：

| 模块 | 必须保留的字段与交互 |
| --- | --- |
| 元信息 | `mineDate`、`articleId`、`articleTitle`；按 `id` 或日期读取已有记录 |
| 论证骨架 | 骨架模板选择；线性/总分模式；总论点、总结、动态分论点、论据、小结、论证方法、方法说明和套用模板 |
| 规范词 | 多行增删、分类选择/新增、普通说法解释、顿号拆分预览；保存后同步规范词库 |
| 经典金句 | 多行增删、原文、来源和释义 |
| 高频动词 | 多行增删、分类选择/新增、使用语境和拆分预览 |
| 万能句式 | 类型选择、多行增删、原文句、套用模板和仿写 |
| 输入能力 | 多行输入、语音输入、保存前表单 flush、加载/保存反馈 |
| 数据操作 | 首次按日期 upsert；之后分模块 PUT；读取、继续编辑和二次确认删除 |
| 每日任务 | 每次保存同步 `mineId`、`lastSection` 和第 2 步；“完成拆解”进入独立小题页 |

禁止继续使用“立意、结构、表达”三个字符串替代上述结构化字段。

### 3.3 小题、反馈与沉淀

- 小题必须独立于三刀编辑页，按任务元数据展示题型、题干、字数和规则。
- 输入自动保存到服务端草稿；至少完成规定自检后才能提交。
- 反馈必须保留材料依据、标准要点或明确规则来源；不能只用关键词正则冒充阅卷结果。
- 表达沉淀保存规范表达、使用场景和来源，并进入可复习资产。
- 完成页展示今日收获、主要改进点和下一次复习，不重复提交开采记录。

### 3.4 资产闭环

- 开采本展示骨架、规范词、金句、动词、句式并可继续编辑。
- 规范词库支持分类、学习/掌握、例句、删除确认和复习。
- 阶梯训练保留造句、仿写、口述三种模式，并从规范词与开采记录生成题目。

## 4. 政治理论完整迁移契约

### 4.1 今日学习包

- 首页保留来源、时长、主题、简介、考点、审核题数、依据数、四步路径和内容门槛。
- 读前判断保持两题、不揭答案、不计错题，保存后进入原文。

### 4.2 原文精读

- 复用原版文章详情的目录、分节、目录/翻页模式、阅读进度和知识框架。
- 保留复制正文、语料采集和完成阅读积分；每日任务还需同步第 2 步。

### 4.3 证据刷题

- 复用原版题目组件与逐题流程：单选即时提交、多选确认、解析、上下题、退出和重开确认。
- 保存用户答案、正确答案、解析、积分、错题和完整结果统计。

### 4.4 错因回收

- 只重点展示错题；全对时抽取边界题复核。
- 每道错题必须选择主体偷换、范围变化、程度变化、因果倒置、概念混淆或记忆不牢之一。
- 保存 `wrongQuestionIds`、`quizAnswers`、`errorReasons` 和 `evidenceReviewed` 后才能完成任务。

## 5. 双端共性功能迁移契约

两个垂直应用均须完整迁移：

- 认证：服务端注册开关、登录/注册校验、统一 token、登录失效回跳。
- 个人资料：头像上传、昵称、邮箱、手机号、修改密码。
- 签到积分：签到日历、连续天数、积分总分与流水筛选。
- 反馈：内容校验、提交状态和采纳积分。
- 数据管理：导出、文件校验、导入确认和恢复结果。
- 统一反馈：同一 Toast、确认框、输入弹层、复制反馈和错误语气。
- 统一设置：主题约束、深色模式、持久化和原生导航栏同步由产品统一决定，不做假入口。

## 6. 迁移顺序与发布门槛

1. 申论：时评详情 → 三刀解剖 → 小题/反馈/沉淀 → 开采本/规范词/阶梯训练。
2. 政治理论：读前判断 → 分节精读 → 原版刷题 → 错因回收 → 专题/错题复习。
3. 双端共性：认证 → 个人资料/改密 → 签到积分 → 反馈/数据管理。
4. 每个模块必须完成 TypeScript、H5、微信小程序构建和实际交互回归后，才可将状态改为“已迁移”。
5. 页面存在但按钮无行为、只显示静态数组或“规划中”，一律判定为未迁移。
