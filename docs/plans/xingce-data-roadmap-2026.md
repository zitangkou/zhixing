把「真题数据」变成「可出题、可展示、可验证」的内容生产底座，分四条主线推进：


## 2. 依赖关系与关键路径

```text
[无依赖，立即]  S1 规律报告 ─┬─→ Q1 数据基线 ──→ Q2 最小样题引擎 ──→ Q3/Q4 扩展 ──→ Q7 闭环 ──→ Q8 规模化

[外部依赖]      用户解析册 ──→ D1/D2/D3 答案接入 ──→ D8 subtype ──→ S2 答案层统计 ──→ R1 反哺 rubric
[回源]          D6/D4/D5 缺陷修复 ──→ 基准集纯净（Q1 前提）
```

**关键路径（最长链）**：S1 → Q1 → Q2 → Q3/Q4 → Q7 → Q8。
**可并行**：S1、P0、D 线（答案接入随扫描）、D6 缺陷修复。
**瓶颈**：解析册扫描进度（外部）、模拟题生成质量验证（内部）。

## 6. 风险与缓解

| 风险 | 等级 | 缓解 |
|---|---|---|
| 解析册扫描进度不可控 → 答案排期漂移 | 高 | 答案接入做「事件驱动」不锁死日期；空窗期用 S/P/Q 无依赖工作填满 |
| 2023/2024 答案长期缺失 → 规律统计答案层样本不足 | 中 | 答案层先以 2025 为准；结构层用 6 年题干不受影响 |
| 模拟题生成双答案/数值矛盾 | 中 | 严格「先真值后题面」+ 程序双求解 + 小样先行，Q2 验证通过才扩 |
| 持久化过度设计拖慢节奏 | 中 | 只做 P0 最小版，SQLite 继续；PG/对象存储设条件门 |
| 三卷共享题修改不同步 | 中 | D10 去重 + provenance 直接复用，hash 仅兜底 |
| 数据缺陷带入基准集 | 高 | Q1 前先 D6 排除高风险 flag；报告标注样本口径 |
