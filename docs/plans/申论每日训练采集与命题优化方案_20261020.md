# 生产申论每日训练采集与命题优化方案

> 日期：2026-10-20（北京时间）
> 状态：核心规则与定时续批已在本地实现；待部署和教研灰度验证。生产核查仍为只读，既有草稿未改写。
> 生产版本：`a34730abc981ad262f47452987206c6c517c1d8a`（与本地当前 HEAD 一致）。

## 1. 要解决的问题

2026-10-20 生产定时生成的申论练习只有两道，且都从同一篇文章生成；归纳概括题偏向宏观责任体系，申发论述题也停留在宏观政治责任表述。目标是让每天进入草稿池的题目更接近国考小题的材料任务，也让考生能从明确的对象、情境和材料证据出发练习，而不是只围绕宏观主题表态。

这不是通过设每日题量指标来解决。材料不适合命题时仍应允许零产出；优先修复候选发现、每日处理范围、题目具体度和审核校准之间的断点。

### 2.2 两道产出为何显得宏观

1. **归纳概括题**标题为“概括落实管党治党政治责任的主要着力点”，设问对象是落实责任的着力点；材料与答案集中在责任体系、主体责任、知责担责履责、问责等组织治理概念。虽然引文和要点能回到材料，但题目没有限定一个具体基层实践、服务对象或问题场景，考生容易变成概念复述。
2. **申发论述题**标题为“围绕‘知责、担责、履责’写短论述提纲”，要求围绕宏观判断写中心论点和分论点。文章提供了责任主体和纪律治理内容，但题目未要求围绕其中一个具体工作难点、责任落实情境或实际治理结果展开，考生训练重心更像概念阐释。
3. 两题都达到现有自动规则分数并通过同模型二次复核，说明当前质量门更擅长检查原文证据、答案覆盖、长度和结构；对“题目是否具体、是否从考生可处理的材料任务出发”缺少独立且可阻断的检查。

## 3. 现行生产链路梳理

```text
人民日报纸版当日目录
  → 拉取正文并放入48小时共享池
  → 联合分析：评论类别、金句/词汇/申论素材候选
  → 申论筛选：正文长度、core/extended类别、申论候选类型、原文证据、候选评分
  → 按类别和候选分排序、正文去重
  → 每任务最多取3篇文章
  → 每篇最多生成2道不同题型
  → 硬规则校验（材料、摘录、题型要点、字数、解析、评分维度）
  → 同一 LLM 再做语义复核
  → 合格题写入待审核草稿；人工审核后才能发布
```

现行限制集中在：

- 共享文章类别被复用为申论命题准入门槛。
- 候选需已有 `shenlunMaterials` 且分数至少 8；但素材候选的评分目标和练习题适配度并不完全相同。
- 按 `core` 优先于 `extended` 排序，容易先处理观点评论；第一批固定 3 篇后没有自动续跑。
- 每篇最多两题、并要求题型不同；没有要求两题必须是两个独立材料任务，也没有跨文章的每日来源多样性检查。
- 生成和复核用同一服务端 LLM，复核不是独立盲审。
- 自动质量门通过不等于题目达到了国考设问的具体度；目前 `task_fits` 关注题型模式，但缺少“具体对象/情境/任务边界”和“考生是否能据材料作答”的专门维度。

## 4. 优化目标与原则

### 4.1 以具体材料任务作为命题单位

每道题都要能明确回答以下问题：

1. **考生对什么作答？**具体主体、对象、服务事项、治理环节或变化范围。
2. **材料给了什么证据？**连续上下文足以支撑要点，事实、动作、对象和结果可定位。
3. **考生要完成什么动作？**概括、分析、提出建议、撰写特定文种或围绕材料进行短论述。
4. **答案边界在哪里？**给定资料范围、字数/文种、身份和受众明确，不需要靠外部常识补答。
5. **为什么像申论训练？**任务结构能映射到真题/教材的稳定考法，而不只是把文章主题改写成一个大问题。

### 4.2 区分“主题宏观”和“设问宏观”

宏观主题可以作为文章背景，但题目必须落在材料里的具体问题、对象、做法、机制、变化或结果上。例如文章谈“基层治理”，设问可以要求概括某类小区如何建立协商和物业管理机制；不能只问“基层治理有哪些重要意义”而让考生靠常识发挥。

申发论述不必一律微观化。若材料本身是观点文章，只有在材料提供具体矛盾、实践或论据链时，才围绕其核心判断做提纲/论证段练习；题目须要求把观点与材料中的具体事实相连，并限制为一项清晰的论证任务。缺乏具体论证支点时，应跳过申发论述题型，而不是硬生成宏观提纲。

## 5. 建议的目标流程

### 阶段 A：全量发现与分层筛选

1. 对当日已采集正文建立完整清单，记录发现数、正文获取成功数、联合分析版本和文章 URL。
2. 让联合分析输出的 `category` 只表示评论/观点素材属性；另行输出申论材料结构信号，例如：具体问题、具体主体、公共服务对象、可定位行动、制度/流程、前后变化、结果证据、材料段落位置。
3. 申论候选准入不再要求 `category in {core, extended}`。优先使用事实性报道、基层案例、公共服务、政策执行、问题解决类的原文结构；评论文章只有存在具体材料证据链时才入围。
4. 用小型规则先淘汰公告、任免、纯会议消息、无正文或严重缺文；对剩余文章按“任务可命性”排队，不用金句/词汇候选分数代替命题价值。
5. 每篇候选保存明确的入选/跳过原因，供后台和教研复盘；不可把被分类过滤的文章静默丢弃。

### 阶段 B：命题前生成材料任务卡

先让模型针对文章提出最多 1—3 个候选任务卡，暂不写答案。每张卡包括：

- 题型与考法参照（真题/教材来源可追溯）；
- 作答对象、材料范围、核心任务和明确限制；
- 拟用连续原文段落及长度；
- 预期要点簇及各自证据锚点；
- 具体性说明：它依赖哪些文章事实，为什么不能由空泛常识直接作答；
- 是否存在材料外知识依赖或材料不足。

只有任务卡通过规则与审核后，才展开参考要点、答案、解析和评分维度。这样能在长答案生成之前先拦住宏观、无边界的题干。

### 阶段 C：按题型的具体命题约束

| 题型 | 必须具备 | 退回/跳过信号 |
|---|---|---|
| 归纳概括 | 明确对象+范围+要素；优先围绕一个具体主体/项目/服务场景，概括做法、问题、原因、变化、成效或特点；给定合理字数 | “主要着力点/重要意义/经验启示”等抽象名词没有限定材料对象或证据范围；题目把文章中心观点直接换成问句 |
| 提出对策 | 材料中的具体问题或执行障碍；建议逐项回应，主体和动作可操作；材料不足的推导须标出依据 | 泛化成“如何加强/如何推动”，建议靠常识堆叠，问题与对策不对应 |
| 贯彻执行 | 身份、受众、场景、文种、目的和信息任务齐全；内容结构服务于文种 | 缺少受众/场景，套固定格式；要求写材料中不存在的正式单位、日期或职责 |
| 申发论述 | 清晰的观点任务+至少两个材料论证支点；练习控制为立意、提纲或一个论证段；要求分论点回扣具体事实 | 只围绕宏观口号表态；材料只有观点、没有可供考生组织的事实/机制；分论点靠补充外部案例 |

归纳概括题的字数上限按任务复杂度和真题参照设置，不以统一扩大字数来掩盖任务范围模糊。申发论述示范答案明确是可能表达，不设唯一标准范文。

### 阶段 D：双层审核

1. **自动硬校验**：原文连续性、摘录完整性、答案长度、要点证据回查、答案覆盖、题型字段与文种要求。
2. **题目具体度审核**：额外要求 `task_specificity`、`material_dependence`、`candidate_answerability`、`scope_bounded` 四项逐项通过。复核问题示例：
   - 考生是否能只根据给定材料完成任务？
   - 题干是否指出一个可识别的对象、场景或要素？
   - 题目是否需要泛泛谈主题、而非处理材料事实？
   - 换成另一篇主题相同但事实完全不同的文章，题干是否仍能原样成立？若可以，说明题干可能过于空泛。
3. **基准题型盲审**：增加“合格的具体题”和“看似通顺但过宏观的反例”，人工盲审新旧规则生成稿，记录题干具体度、材料依赖度、考生可作答性、答案证据覆盖和题型贴合度。
4. **人工发布门**：所有生成结果继续保持草稿；教研编辑能查看候选文章、题目任务卡、原文上下文、每条证据、退回原因和规则版本，再决定采用/修改/拒绝。

不能只要求同一 LLM 在提示词中“更具体”。应让每个具体度判断有字段、有反例、有可记录的审核结果。

### 阶段 E：处理完整候选队列和来源多样性

- 将“每批最多处理 3 篇”与“每天只处理 3 篇”分开配置。保留小批次可便于恢复，但定时任务应在可控总预算内自动续跑后续候选，直到达到当日处理上限或候选耗尽。
- `partial` 表示还有未处理候选时，应触发下一批或生成明确待续跑状态；失败重试和正常续批分开统计。
- 候选按任务可命性和内容具体度排序，并在首批中平衡观点文章与事实报道；不要让评论分类天然压过民生治理案例。
- 每篇最多发布草稿数仍受质量限制；同篇文章可以有不同题型，但只有在材料片段和能力任务确实独立时才保留两题。
- 统计“草稿数、来源文章数、候选处理覆盖率、题型分布”，监测多题集中到一篇宏观评论的情况；不设低质量的每日凑数要求。

## 7. 实施顺序与验收

### P0：生产当天可观察性与续批（核心实现完成）

- 后台日报清楚区分：纸版总文章数、正文成功数、联合分析完成数、申论候选数、已处理数、剩余数、生成/退回/跳过/失败数。
- 定时流程能继续处理剩余候选；续批失败不丢失已有草稿和处理游标。
- 已实现：单批最多3篇，定时每日最多12篇；`partial` 且有剩余、无失败的批次会创建下一批；运行失败继续走失败重试路径。累计处理 URL、结果和剩余候选写入现有进度 JSON，不增加数据库列。
- 待验收：部署后用实际候选队列确认跨批去重、候选耗尽和每日上限行为；当前环境未触发生产补跑。

### P1：申论候选准入与排序（核心实现完成）

- 解除申论命题与评论 `category` 的硬绑定；增加事实性、民生服务、基层治理文章的任务结构识别。
- 候选评分独立评估题型可命性，不能仅继承素材候选 8 分。
- 已实现：取消 `category` 硬过滤；只有原文可回查且类型属于问题、案例、对策、执行行动的候选可进入，按这些具体锚点类型数和候选评分排序。
- 已测试：模拟 `category=exclude` 但存在具体案例原文证据时会进入候选。两篇生产样本需部署后重新生成候选才能确认具体记录，纯公告/会见消息的排除依赖上游没有提供上述可核验锚点。

### P2：设问具体度及考生可作答性（规则门槛已实现，灰度待完成）

- 已实现：生成结果须包含 focus/scene/anchor 任务卡；代码校验焦点、情境和摘录内事实锚点；语义复核新增并强制 `task_specificity`、`material_dependence`、`candidate_answerability`、`scope_bounded` 四项通过，任务卡保存在质量报告内。
- 待完善：当前任务卡与答案在同一次生成调用中产生，尚未拆成独立的先审任务卡阶段。需要结合盲审数据再确认是否值得增加调用与流程复杂度。
- 现有真题/教材 benchmark 继续作为题型任务结构参照；具体民生治理正反例与不同题型边界样本仍需教研盲审补齐。
- 验收：盲审对比至少覆盖 7 天或 50 个候选任务卡；宏观空题拦截率、合格具体题保留率、人工修改率按题型统计，教研确认后再启用新规则。

### P3：小范围灰度

- 新旧规则并行生成草稿，不自动发布；同一组样本由教研人员盲审，不显示规则版本。
- 逐题记录采用、修改后采用、退回及原因；先观察命题质量和素材覆盖，不以题量作为唯一目标。
- 通过一轮复核后再考虑切换默认规则；回滚时保留旧版本和审核数据。

## 8. 建议监测指标

| 指标 | 用途 |
|---|---|
| 全文获取率、联合分析完成率 | 判断采集链路是否漏文或上游失败 |
| 申论候选覆盖率、按文章类型分布 | 发现评论分类错误挡掉事实报道 |
| 候选已处理比例、剩余候选年龄 | 发现定时只跑首批、不续批 |
| 每道题的题目具体度/材料依赖/范围边界 | 识别宏观套题 |
| 草稿来源文章数与同文题目数 | 发现来源集中 |
| 初筛通过率、语义复核退回率、人工修改率 | 校准各道质量门 |
| 按题型统计的采用率及主要退回原因 | 发现申发论述或归纳概括单类偏差 |

指标用于查问题，不设置硬性每日出题数。出现零产出时要能指出是采集不足、候选准入、题目不适合、质量退回还是服务错误。
