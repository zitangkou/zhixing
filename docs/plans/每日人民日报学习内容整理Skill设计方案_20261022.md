# 人民日报学习内容整理 Skill 设计方案

> 日期：2026-10-22（北京时间）
> 状态：扩展性方案；尚未创建 Skill。
> 用途：作为可公开分享和开源的学习内容整理工具。只产出 Markdown 学习文档及其 PDF 版本，不承载账号运营和平台发布。

## 1. 设计目标

提供一个可组合、可续跑的 Skill：用户只给一个人民日报日期，Skill 就能发现文章、筛选分类、输出待确认队列；用户确认文章后，Skill 自动按文章类型和内容适配分析任务，并生成有出处、可复习的 Markdown 文档。用户需要时，再将同一文档导出为 PDF。

Skill 可以整理以下学习内容：

- 申论文章结构与“三刀”解剖：主题、立意、论证结构、事实论据、表达迁移。
- 理论文章时政套题：基于文章观点、概念和事实制作可核对的学习题组、答案及解析；明确标注为学习练习，不冒称正式真题。
- 金句与表达：原文句子、上下文、出处、句式结构、适用位置、迁移示例和使用边界。
- 申论素材与词语：案例、问题、做法、机制、结果、规范表达、成语/固定表达/重点词语。
- 行测学习线索：言语理解语境和词语辨析；有可靠数据来源时的资料分析学习示例；其他题型仅在题型依据充分时提供分析。

文章不必覆盖所有内容类型。Skill 应按材料特点选择适合的学习模块；没有足够材料依据时明确跳过，不为凑数生成。

## 2. 明确范围界限

### Skill 可以做

1. 读取用户提供的文章、文件、链接，或在工具可用且用户指定范围明确时查找对应文章。
2. 记录标题、来源、刊发日期、版次/栏目（能核实时）、原文链接及访问日期。
3. 对原文做学习用途分析，给关键判断和摘录保留来源锚点。
4. 输出结构清晰、可编辑、可复用的 `.md` 文档。
5. 用户要求 PDF 时，把已确认的 Markdown 内容导出为 `.pdf`，并检查页码、中文字体、表格和换页效果。
6. 对用户指定的错误或审核意见修改对应文档，并保留清晰的来源和修改状态。

### Skill 不做

- 不生成公众号、小红书、知乎、抖音等平台的发布文案、标题、摘要、标签、运营方案或账号引流话术。
- 不生成公众号 HTML、长图、封面、社交平台卡片、图片、配音、字幕、短视频、成片或发布包。
- 不连接或操作用户的公众号、小红书等账号，不发送消息，不自动发布。
- 不携带或调用私有品牌模板、Logo、字体、封面图库、平台账号、Cookie、API Key 或个人云盘凭据。
- 不把人民日报全文复制进输出文档或 PDF。只保留分析所必需的短摘录，并标明出处；长文输入优先由用户提供，分析结果以概述和结构化笔记为主。
- 不把改编练习冒称历年真题，不把仿写冒称人民日报原句，不把推断或外部知识伪装成原文事实。

公众号和小红书等私有运营工作流仍由用户在独立的私有环境中完成。本 Skill 的 Markdown/PDF 学习内容可以作为私有运营的上游素材，但不包含运营加工步骤，也不因上游有学习文档就自动生成发布物料。

## 3. 建议的 Skill 形态

先做**一个 Skill**，内部采用“稳定核心流程 + 可插拔内容路由”，暂不拆成多个子 Skill。对使用者保持一个入口；在 Skill 内将采集、分类、用户确认、内容生成、文档输出分成独立阶段。内容域通过小型路由注册表扩展：

- `three-knife`：评论/观点文章的申论三刀解剖。
- `political-theory-questions`：理论文章时政套题。
- `quotes`：评论或观点句的金句与表达整理。
- `shenlun-materials`：案例、问题、做法、机制、规范表达和词语。
- `xingce-learning`：言语理解语境，或经来源与口径核验的数据学习。
- `daily-digest`：把当日多篇文章的入选内容汇总到每日学习简报。

同一篇文章允许命中多个路由，不要求文章类型与产物一一对应。例如，理论文章可以同时进入时政套题、金句和规范表达评估；民生案例报道可以进入申论素材和概括/对策练习评估。最终产出仍按用户确认的文章和模块执行。

### 四种使用入口

| 入口 | 用户提供 | Skill 行为 | 继续条件 |
|---|---|---|---|
| 日期批次（默认） | 一个日期，如“整理 2026-10-22 人民日报” | 发现当日文章、核验元数据、分类打标、筛选候选、输出待审核文章清单和建议产物 | 用户确认文章/模块后，批量生成文档 |
| 日期全流程 | 日期并明确说“直接全量处理/按默认规则生成” | 在规则阈值内自动选择候选并生成相应 Markdown；保留所有筛选理由和草稿状态 | 不需要逐篇选择；仍不发布任何内容 |
| 单篇定向 | 指定文章链接/文件/标题，并说“做三刀/时政套题/素材卡”等 | 跳过日报全量筛选，只跑指定内容路由；必要时建议额外适配路由，但不擅自扩产 | 来源核验通过即可生成 |
| 续跑批次 | 已有运行批次 ID、日期或“继续上次” | 读取 manifest，跳过已完成路由，只重试失败/退回项 | 对未确认文章仍需确认；不得重做覆盖已通过文档 |

默认只有日期时先完成发现和候选审核清单，再暂停在选文确认点。这兼顾“日期即可启动完整工作流”和“先由用户挑选文章”；如果用户配置了 `selection_policy=auto` 或本次明确要求直接全量处理，才在同一批次自动完成筛选与文档生成。此设置只影响本地学习文档生产，不触发外部发布。

### 文件结构建议

```text
rmrb-learning-notes/
├── SKILL.md                    # 触发场景、来源原则、模块路由、边界、交付方式
├── agents/openai.yaml          # Skill 在 Codex 中的简短名称和描述
├── references/
│   ├── source-and-citation.md  # 来源核验与摘录要求
│   ├── routing-registry.json   # 文章标签到内容路由的适配规则
│   ├── three-knife.md          # 三刀解剖输入/输出字段与质量检查
│   ├── political-theory.md     # 理论文章时政套题与解析规则
│   ├── quotes-and-materials.md # 金句、案例、词语的结构化记录
│   ├── xingce-learning.md      # 行测题源和数据校验边界
│   └── markdown-pdf.md         # MD/PDF 输出约定
└── scripts/
    ├── discover_sources.py     # 可选：稳定的来源发现/抓取适配
    ├── build_manifest.py       # 确定性元数据、去重、状态与清单
    ├── validate_documents.py   # 引用、必填字段、输出完整性检查
    └── export_pdf.py           # 可选：Markdown 转 PDF
```

避免首版绑定某个新闻网站 DOM、浏览器自动化工具或私有本机路径。来源抓取采用适配器边界；可用网页工具、用户文件或后续可替换的来源插件实现。manifest、去重和状态管理使用稳定 schema。LLM 负责语义分类与内容分析，脚本只负责可确定的字段校验、指纹、文件名、状态和 PDF 转换。工具/依赖缺失时降级为用户提供原文，并明确报告，不虚报全量采集完成。

## 4. 输入、流程与交付

### 输入方式

- 日期：启动该刊期发现、筛选、分类和候选审核队列。
- 一篇文章：URL、用户本地文件、标题或粘贴正文。
- 内容模式：三刀、时政套题、金句、申论素材/词语、行测学习或每日简报。
- 批次策略：默认 `review-first`；可在当次明确指定或设置为 `auto`。
- 输出格式：默认 Markdown；用户明确要求时附 PDF。

缺少正文时先使用可用的原始来源；网页无法访问、日期不明或来源信息缺失时如实说明，并请求用户提供文章文件或补充信息。不能依靠搜索摘要生成带事实判断的完整学习内容。

### 日期批次流程

1. 发现目标日期的可访问文章；保留各来源的发现数量、抓取成功数量、失败 URL 与失败原因。不同来源/版面分开统计，不把部分发现宣称为全报完整清单。
2. 核验标题、日期、版面/栏目、作者（页面提供时）、URL、正文完整性和重复项；来源不完整的文章可列入待核验区，不进入自动生成。
3. 为每篇文章建立内容地图：文章体裁与主题标签、对象/问题、主体行动/机制、变化/结果、论证链、可核验数字、段落证据锚点。
4. 路由评估为多标签，不用单一文章类别硬排斥其他用途。按 `routing-registry.json` 逐路由给出 `candidate / not_suitable / needs_review`、匹配依据、证据锚点和建议产物。
5. 输出文章审核清单：来源信息、短摘要、路由标签、建议学习文档、筛选理由、完整度/置信状态、用户可确认的文章 ID。清单自身为 Markdown，尚未确认的文章不生成完整学习文档。
6. 用户确认文章及模块后，逐篇运行对应路由，形成 Markdown；需要 PDF 时为所选文档导出 PDF。
7. 更新批次 manifest 和 README：区分已发现、待核验、待确认、已确认、处理中、已完成、跳过、失败；记下每个产物和模板版本。

### 单篇定向流程

1. 核验用户指定文章的身份和来源；标题相似但来源不同、日期/版面不一致时标记歧义。
2. 按用户明确指定的任务选择路由。例如：评论文章 → 三刀；理论文章 → 时政套题；民生实践报道 → 申论素材/概括练习；数据报道 → 数据学习/资料分析评估。
3. 对文章同时适配多个路由时可列出建议，但只执行用户指定项；用户说“按适配内容都整理”时，才运行所有通过准入的路由。
4. 生成文档、检查证据和结构，更新运行记录。

### 批次状态与安全续跑

每个来源和每个内容路由分别记录状态；单篇失败只影响对应路由。推荐最小状态：

```text
source: discovered → verified → classified
article: pending_review → selected | skipped
route: candidate → approved → running → completed | failed | not_suitable
artifact: draft → checked → accepted
```

用 `(source_id, route_id, ruleset_version)` 作为路由处理幂等键。重跑时不覆盖用户已经确认的文档；只重试失败项、被退回项或用户明确要求重生成的路由。用户修改确认范围后保留历史清单和变更记录。

### 可扩展路由与兼容性设计

路由采用注册表驱动，新增内容类型时优先新增独立 reference 和模板，不改日期发现、审核队列、续跑等核心流程。每个路由在 `routing-registry.json` 中声明：

- `route_id`、显示名称、适用文章标签与排除条件。
- 最低证据要求、所需输入、输出文档类型及模板版本。
- 内容校验项、默认是否启用、成熟度（`stable` / `experimental`）。
- 失败时的降级产物，例如无法出题时改为知识梳理，缺正文时只输出待核验条目。

一篇文章可通过多个路由评估，也可由用户明确指定路由；每条路由独立给出适配结论和证据。核心流程只识别注册表约定，不依赖具体题型的内部写法。

运行数据使用带 `schema_version` 的轻量 JSON/JSONL 记录，至少覆盖 `SourceRecord`、`ArticleAssessment`、`ReviewSelection`、`ArtifactRecord`。字段新增保持可选并提供默认值；读取未知字段时忽略，遇到不兼容主版本时给出明确升级提示。Markdown 才是面向用户的正式产物，机器记录用于索引、断点续跑和审计。

### 建议 Markdown 文档

- **单篇学习笔记**：来源信息、文章摘要、核心结构、模块分析、原文证据索引、学习结论、待核实项。
- **文章待审核清单**：候选文章编号、标题、日期/版面/链接、体裁标签、建议路由、路由适配理由、证据提示、核验状态和确认栏。
- **每日学习简报**：已确认文章的学习结论与文档索引；候选/待审核文章与已完成内容分区展示。
- **时政套题**：题目、题型、选项/设问、答案、逐项解析、文章依据、难度/知识点、练习性质说明和待核实项。题型与数量由文章适配度决定，不固定凑题。
- **金句/词语清单**：每条记录原文、上下文、解释/结构、学习用途、迁移示例、边界、出处。
- **行测学习笔记**：题源类型、真题参照（如有）、原始数据及来源、推导过程、答案验证；未通过唯一性或数据校验时不列为练习题。

PDF 是相同学习内容的阅读版，不增加新结论，也不把未核验草稿包装为正式教材。

## 5. 内容质量与来源规则

### 通用规则

- 文章事实、人民日报原句、模型概述、个人分析和示范仿写使用清晰标签区分。
- 原句逐字核对，不能把多处摘录拼成一句；节选句应标注节选并保留上下文线索。
- 每条事实案例保留主体、行动、结果及其对应证据；没有原文依据的成效不作断言。
- 外部背景仅在确有必要且可核实时补充，单列来源，不混写成文章原意。
- 文章不适合某一模块时写明原因；不能靠补充常识强行做成题。
- 输出应便于学习与复核：短摘录、准确出处、可迁移方法和适用边界优先于大段复述。

### 三刀/申论规则

- 仅在文章存在可拆解的核心判断、论证推进或具体实践逻辑时使用三刀分析。
- 说明文章如何立意、如何组织分论点、如何使用“主体—做法—结果”等证据，并给出可迁移的方法。
- 练习题参考真题/教材的考法结构，但题目必须注明是基于文章设计的练习，不称作真题。
- 仿写标注为“学习示范”，不得冒充原文或真实政策成效。

### 理论文章时政套题规则

- 先从理论文章识别核心概念、基本判断、因果关系、实践要求和原文事实，再选择合适的客观题/简答题型；题量按内容决定。
- 每题答案必须能定位到文章或明确引用的权威来源；易混选项要能解释区别，不能靠“看起来合理”造干扰项。
- 记录题目类型、答案、解析、来源位置和覆盖知识点。标注“学习练习/据文章整理”，不冒称官方题、真题或权威题库。
- 若文章只有抽象主张，无法形成有区分度且可验证的题目，则输出知识梳理笔记，不强行做套题。

### 金句、素材和词语规则

- 金句按能否理解、记忆和迁移筛选，不以固定数量为目标；记录句子在原文中的位置和上下文。
- 案例、问题、措施、机制、规范表达和词语分类型保存，避免统称“素材”而丢失用途。
- 词语解释结合原文语境；原句、释义和仿写分开。引用语录须区分人民日报文章中的转引出处与可核实的原始出处。

### 行测规则

- 行测真题用于校准题型和考法；若引用真题，记录试卷年份、题号和可核验来源。
- 资料分析必须记录数据年份、单位、统计口径、来源和计算过程；数据不足或口径不一致就只做素材说明，不出题。
- 言语练习须验证语境自然、选项区分有效、答案具有唯一最优性。
- 判断推理和数量关系不从一般新闻主题强行转题；不能证明题型和答案可靠时停止生成题目。

## 6. 开源与私有内容隔离

公开 Skill 包只应包含：通用工作流、通用字段结构、可公开的方法说明、空白 Markdown 模板、无用户数据的测试样例及必要的通用导出代码。

以下内容留在私有运营目录，不进入公开仓库、公开 Skill 包或示例 PDF：

- `/Users/dnn/Projects/学习物料/` 下的私有运营规则原文、当日选文、未发布文章包、内部审核意见和客户/读者数据。
- 公众号、小红书等发布规则、标题/封面/账号引流策略、商业运营复盘及平台账号资料。
- “范文精读/杜衡阁”等私有品牌资产、Logo、字体、封面图片、Canva 模板 ID、视频工程与配音配置。
- 服务器地址、凭据、Cookie、模型 API Key、私有路径、自动化任务 ID 和外部服务账号信息。
- 未获授权的人民日报全文、教材扫描件、商业题库原文和整页 PDF。

开源仓库的测试样例应使用短摘录、公开链接、合成数据或已确认可再分发的内容。README 和 Skill 描述只说明学习整理用途，不暗示人民日报官方合作、官方题库或官方认证。

开源版本与私有运营流程的关系：Skill 输出的学习 Markdown/PDF 可被用户自愿选作私有运营的输入；后续要改写为公众号/小红书等内容，应在私有工作区单独处理，并由用户另行要求。不能让公开 Skill 自动读取或改写私有运营目录。

兼容性要求：所有目录可配置且默认相对当前工作区；不写入个人绝对路径。来源采集、模型分析、PDF 导出通过可替换适配器或清晰的可选步骤接入；缺少某个工具时应退化为用户提供正文、Markdown 输出或跳过 PDF，而不是让整个 Skill 无法使用。不得假设用户有特定 MCP、浏览器插件、云服务或付费 API。密钥从环境变量或用户自己的配置读取，不写入 Skill、日志和产物。基础工作流、字段说明和空白模板必须随 Skill 一起分发，确保离线或换模型时仍可完成手动输入到 Markdown 的主流程。

## 7. 创建和验收顺序

### MVP

1. 创建单一 `rmrb-learning-notes` Skill：精简的 `SKILL.md` 负责识别输入模式和调度，按需读取路由规则、来源规则、字段规范和 Markdown 模板。
2. 首批注册稳定路由：三刀解剖、理论文章时政套题、金句/词语、申论案例素材、每日候选审核清单；行测学习先标为实验路由，数据和答案校验通过后再开放自动出题。
3. 支持日期批次（默认先审核）、明确要求的日期全量处理、单篇指定路由、按批次续跑四种入口；各产物以 Markdown 为主，PDF 显式可选。
4. 用真实但可再分发的短样例覆盖评论文章、理论文章、案例报道和数据报道；验证多路由、路由跳过、候选确认、部分失败续跑、来源证据和版权边界。
5. 检查公开包能脱离私有目录独立运行，且没有私有路径、品牌资产、密钥、发布文案或未经授权的大段原文。

### MVP 验收标准

- 给定链接或原文可输出来源清楚的 Markdown 学习笔记。
- 仅给日期时能形成有来源状态和筛选理由的审核清单；用户按文章 ID 和路由确认后，能只处理所选内容。
- 用户明确要求日期全量自动处理时，系统按路由准入规则生成文档并记录跳过项、失败项和证据状态。
- 指定单篇评论文章可生成三刀；指定理论文章可生成有出处的时政练习；指定素材文章可生成案例/概括学习文档。路由不适配时说明依据并给出可行的降级文档。
- 重跑批次能识别已完成产物，不覆盖已确认文档，并能从单篇单路由失败处续跑。
- 同一篇文章可按用户目标只生成一个模块；不适用的模块会跳过并说明理由。
- 人民日报原句、分析和仿写能清楚区分；案例和数据有证据链。
- 不生成或提及公众号/小红书发布物料，不生成图片/视频。
- PDF 与 Markdown 内容一致，中文、表格和分页可读。
- 缺来源、缺正文、数字口径不清或题目无法验证时能停在草稿/待核验状态。
- Skill 可脱离 `/Users/dnn/Projects/学习物料/` 独立工作，不包含私有绝对路径依赖。
- 无浏览器、MCP、特定模型 API 或 PDF 工具时，用户仍可粘贴正文并完成 Markdown 主流程；缺少可选能力时有清楚的降级说明。
