# 知行管理后台 · 创意平台产品与设计实现方案

日期：2026-10-21
状态：首期已在本地实现，待用户验收与部署；不表示生产已上线。
范围：共享管理后台 `/manage/` 与管理 API；首期不新增学员端或小程序入口。

## 1. 产品定位与关键决策

把散落备忘录中的念头，变成可查找、可关联、可实践、可复盘的个人创意资产。推荐菜单名称「创意平台」，首页名称「创意工作台」。

核心闭环：**随手捕捉 → 整理成形 → 选择验证 → 记录实践 → 沉淀结论 → 再次应用**。

最重要的产品决策：

1. 记录时只要求一段文字，名称可以稍后补。先保留当下想法，再补结构。
2. 类型、方向和状态分开。比如「内容选题 / 抖音 / 待验证」表达三个维度，不能混成一个分类。
3. 一个统一创意对象，支持父子关系和横向关联。大方向、系列主题、单条选题都可记录，不强迫所有想法先建项目。
4. 每个正在推进的创意都有一个下一步；每次实践记录做了什么、结果如何、下一步是什么。
5. 允许暂存、搁置、否定。沉淀失败原因也有价值，不以创意数量或全部完成作为目标。
6. 创意平台负责构思与验证，现有账号运营负责具体发布包和审核。首期通过结果链接连接，后续再接结构化转换。

首期以个人使用为主，但保留创建者、负责人和可见范围，为以后多人协作留好边界。

## 2. 场景与对象关系

| 场景 | 记录方式 | 后续动作 |
|---|---|---|
| 突然想到一句话 | 快速记录，默认进入灵感箱 | 稍后命名、分类、合并或归档 |
| 刷到短视频产生想法 | 粘贴分享原文/链接，并写「启发了我什么」 | 保存截图、摘录或时间点，避免只留链接 |
| 阅读书籍有所触动 | 书名、作者、章节/页码、摘录 | 关联可应用的主题或产品想法 |
| 想打造抖音内容矩阵 | 新建「项目方向」创意 | 拆分账号定位、内容系列、验证任务 |
| 想到一个好选题 | 新建「内容选题」，可关联上级系列 | 补受众、切入点、表达形式并试做 |
| 做了一次实验 | 在创意内添加实践记录 | 留证据、指标和继续/调整/停止的判断 |
| 旧想法重新有价值 | 从搁置或归档恢复 | 保留历史结论，追加新的验证记录 |

推荐关系示例：

```text
抖音公考内容矩阵（项目方向）
├─ 新手入门账号（项目方向）
│  └─ 每天拆一个常见误区（内容系列）
│     ├─ 为什么刷题越多反而越焦虑（内容选题）
│     └─ 复盘错题到底应该写什么（内容选题）
└─ 时评表达账号（项目方向）
   └─ 一段时评的三种表达（内容系列）

书籍摘录/视频截图/站内文章 → 可关联多个创意
实践记录 → 属于一个创意，可关联多个参考物料和成果链接
```

树关系表示归属；「启发自、类似、可组合、依赖」表示横向关系。首期只提供父子和普通关联，其他关系类型后续扩展。父级完成不自动完成子项，子项完成也不自动完成父级。

## 3. 信息结构与字段

### 3.1 创意主记录

| 字段 | 规则与用途 |
|---|---|
| 名称 | 最长 120 字；快速记录为空时以原文前 30 字生成，整理时可改 |
| 原始灵感 | 保留首次录入内容，便于找回最初语境；后续修订留时间线 |
| 描述 | Markdown，记录完整构思；支持预览与编辑 |
| 类型 | 未分类、随手想法、项目方向、内容系列、内容选题、产品功能、实践方法；首期固定字典 |
| 方向标签 | 多选，如抖音、公考、摄影、商业；标签不是类型，允许跨方向 |
| 状态 | 灵感箱、待验证、实践中、已沉淀、已搁置；见状态规则 |
| 优先级 | 普通/重点/优先；默认普通，不强制复杂评分 |
| 收藏 | 独立标记，方便随时回看 |
| 父级创意 | 可空，首期界面建议最多展示三层；服务端防循环 |
| 关联创意 | 多对多，可双向跳转，防自关联和重复关联 |
| 负责人/创建者 | 默认为当前管理员；禁止客户端伪造创建者 |
| 下一步/计划日期 | 一个简洁动作及可选日期；实践中必须有下一步 |
| 复盘日期 | 可选；首页展示到期项，首期只做站内提醒 |
| 可见范围 | 默认仅自己；可主动共享给具备创意权限的管理员 |
| 沉淀结论 | 结论、适用条件、继续/调整/停止；已沉淀时必填结论 |
| 时间字段 | 创建、更新、最近实践时间、归档时间、删除时间 |

归档是独立字段，表示从日常工作区收起，保留原状态；删除进入回收站。收藏、优先级也不占用状态。

### 3.2 按类型提供提示模板

提示模板只预填 Markdown 小标题，不增加一堆必填字段，不以一个庞大 JSON 表单承载所有业务。

| 模板 | 提示内容 |
|---|---|
| 项目方向 | 想解决的问题、目标人群、目标结果、资源与约束、最小验证、停止条件 |
| 内容系列 | 面向谁、核心承诺、固定内容结构、差异化、可持续来源、首批选题 |
| 内容选题 | 一句话主题、受众痛点、开头钩子、核心观点、表达形式、行动引导、验证方式 |
| 产品功能 | 使用场景、现有困难、方案、预期价值、最小范围、验证方式 |
| 实践方法 | 假设、步骤、投入、预期效果、观察方式、适用边界 |

### 3.3 参考物料

统一支持链接、图片、文件、文字摘录、站内内容引用。字段包括标题、物料类型、来源平台/书名、作者、URL、页码/时间点、摘录、个人启发、附件、创建者及时间。

- 保存短视频分享原文，从中提取 HTTP/HTTPS 链接，保留原文；首期不依赖自动抓取或平台授权。
- 「引用内容」与「我的想法」分开，防止以后分不清自己的观点和原文。
- 一个物料可以被多个创意引用；关联时可另写针对该创意的启发。
- 外链失效时仍能看到摘录和截图；不承诺自动下载第三方视频。
- 首期站内引用支持经校验的文章 ID/详情地址；更多内容域通过引用适配器逐步接入。
- 物料删除采用回收站策略；解除某个创意关联不会删除物料。共享创意引用私人物料时，必须提示并由用户明确共享该物料，否则其他人只看到「无权访问的物料」。

### 3.4 实践记录

实践不是一条普通评论。每次记录包含：日期、标题、类型（研究/制作/测试/发布/复盘）、采取的行动、假设与预期、结果与证据、投入时长/费用（可选）、判断、下一步、相关物料和成果链接。

指标允许多项，采用「指标名、数值、单位、观察周期、来源」结构。如播放量、收藏率、有效咨询数都可手工录入；百分比统一在接口中约定为 0–100。结果不达预期可以如实标记，不能仅以某条视频播放量判定整个方向成功。

下一步可以同步更新创意主记录，需要在同一事务内完成。记录修订保留版本或修改事件，系统生成的状态事件不可直接编辑。

## 4. 状态与日常使用

| 状态 | 含义 | 进入条件 |
|---|---|---|
| 灵感箱 | 刚记下、还没整理 | 快速记录默认进入 |
| 待验证 | 值得试一试 | 明确想法与验证动作 |
| 实践中 | 已开始投入 | 填写下一步，计划日期可选 |
| 已沉淀 | 形成阶段结论 | 填写结论，不要求一定成功 |
| 已搁置 | 暂时不做 | 填写原因，可设下次回看日期 |

允许重新打开与退回灵感箱；任何状态变化留操作者、前后状态、原因与时间。归档后只读，恢复后再操作；删除后不可修改，恢复后保留原状态。批量操作首期只支持标签、归档和移入回收站，不批量改变需要填写结论的状态。

每日流程建议：随时记录，空闲时清理灵感箱；每周挑选少量重点项，给出一个足够小的动作；做完即记结果，周末回看。平台提供「我的待跟进」「已到复盘日期」「实践中 14 天无新实践」视图。14 天为可调整产品默认值，不是自动判定失败的依据。

首页按待办价值排序，避免堆积图表。首期不安排后台定时推送，到期项由查询计算；未来增加通知再单独设计消息渠道和通知设置。

## 5. 页面和交互设计

管理后台新增一级分组「创意平台」，提供工作台、创意库、参考物料、回收站四个入口。灵感箱和实践看板作为创意库内的预设视图，减少菜单层级。

### 5.1 工作台 `/creative`

```text
创意工作台                             [快速记录]
[待整理 12] [实践中 3] [今日待跟进 2] [待复盘 1]

我的下一步                         最近捕捉
□ 试做一条 30 秒样片  今天           为什么错题越积越多…
□ 整理矩阵账号定位    明天           读书触发的系列想法…

重点创意                           久未推进
抖音内容矩阵 · 实践中               内容系列 A · 18 天无实践
```

数字全部可点击进入对应筛选；数量只统计当前管理员有权查看且未删除的数据。工作台默认以本人负责项为主。

### 5.2 快速记录

桌面右上角常驻「快速记录」，弹窗仅显示大文本框、可选链接/图片、保存按钮；「更多信息」折叠。一次粘贴混合文本也能保存。支持 Ctrl/Cmd+Enter 保存，输入法组合期间不触发提交。

默认个人可见、未分类、灵感箱，不要求预先选择方向或项目。空文本且无物料时阻止提交；只有链接/图片时以分享文本或文件名生成标题。保存后显示「继续记一条 / 打开详情」。失败保留输入；成功后再清空；重复点击和网络重试通过请求幂等键防重。

手机使用同一管理后台的响应式快速记录页，登录后可收藏该地址。首期支持系统输入法语音输入，不引入录音上传与转写；微信分享直达、浏览器扩展、AI 整理均列为后续。

### 5.3 创意库 `/creative/ideas`

上方搜索，下面类型、状态、标签、负责人、可见范围、日期、收藏筛选；支持表格/卡片/状态看板切换。默认展示未归档且未删除项。

- 表格列：名称、类型、状态、标签、下一步、计划日期、最近实践；较长描述收起。
- 看板每列分页加载，显示该状态总数；首期通过卡片菜单切换状态，避免未填条件就拖入已沉淀。
- 搜索首期覆盖名称、原始灵感、描述；物料与实践各自提供关键词检索，并可跳回所属创意。跨对象统一搜索后续再做。
- 筛选写入 URL，刷新和分享链接保留条件；无权限的详情返回统一不可访问提示。
- 无结果给出清空筛选入口；首次无内容展示两个可选择的示例模板，不自动插入样例数据。

### 5.4 创意详情 `/creative/ideas/:id`

头部显示名称、状态、收藏、优先级和操作；主体为「构思 / 参考物料 / 实践与时间线 / 关联」四个页签，右侧显示负责人、日期、标签、父级、下一步。窄屏将属性折叠到下方，保留记录实践按钮。

实践时间线混合显示人工实践和系统事件，可只看实践；概览显示最近结论、下一步和子创意进度。更新表单显式保存；离开有未保存修改时提示。首期不做覆盖式自动保存，使用版本号解决多标签页冲突。

管理端沿用 Vue 3、Element Plus 和 `server/admin-web/src/styles/main.css` 的现有样式体系；使用现有 token、px 单位、scoped 样式和模块前缀，保持加载、空态、失败重试与保存反馈一致。具体 token 接入在开发前核对，不能直接假设管理端 `@` 指向学员端样式目录。

## 6. 两个完整业务示例

### A. 打造抖音内容矩阵

1. 随手记录：「我想做一组公考内容账号，一个讲入门，一个拆表达，用内容把用户引向学习产品。」
2. 整理为「项目方向」，描述里明确人群、账号差异和资源上限；拆出两个子方向，不先建复杂账号管理模块。
3. 加入参考账号链接与截图，并写清值得借鉴的内容结构。
4. 设置下一步：「只选一个方向，制作三条不同开头的样片」，进入实践中。
5. 为样片建立子选题；每条记录发布地址、制作耗时、同一观察周期的数据和用户反馈。
6. 复盘确定保留哪个方向、为什么；先验证一个方向，再决定是否扩展矩阵。

### B. 想到一个内容主题

1. 记录：「把同一个申论观点分别讲给高中生、大学生、职场人听。」
2. 分类为内容选题，关联「一段时评的三种表达」系列。
3. 补开头钩子、核心观点和三种表达样稿，关联一篇站内文章与一段阅读摘录。
4. 记录实践：「做了 45 秒样片；第二种表达更易懂，但前 5 秒铺垫太长。」
5. 下一步：「删掉背景介绍，用三句表达直接开场再试」；即使尚未发布也能完整追踪。

## 7. 技术落地与现有系统衔接

以下为基于仓库的设计判断：后台已有 Vue 3 + Element Plus + Axios，后端已有 FastAPI、SQLAlchemy、JWT/RBAC；`content_ops.py` 存在发布包与审核能力，但当前侧栏未露出账号运营入口，不能假设用户可直接导航使用。

新增独立 creative 域，不复用学习计划或学员行为事件表。管理审计与学员 `activity_events` 分开；如果确需写学员事件，仍只能通过现有 `record_event()`。

### 7.1 拟新增文件与接入点

| 层 | 路径/动作 |
|---|---|
| ORM | `server/app/models/creative.py`，由 `models/__init__.py` re-export |
| Schema | `server/app/schemas/creative.py`，由 `schemas/__init__.py` re-export |
| 服务 | `server/app/services/creative_service.py`，封装状态、归属、引用和事务 |
| API | `server/app/api/admin/creative.py`，在管理 `routes.py` 聚合 |
| 管理 API 客户端 | `server/admin-web/src/api/creative.ts`，复用 `api/http.ts` |
| 页面 | `views/creative/Workbench.vue`、`IdeaList.vue`、`IdeaDetail.vue`、`MaterialLibrary.vue`、`RecycleBin.vue` |
| 私有组件 | `QuickCapture.vue`、`IdeaProperties.vue`、`PracticeTimeline.vue`、`MaterialPicker.vue` |
| 路由菜单 | 同步 `router/index.ts`、`config/nav.ts` 的分组及标题、`config/featureVisibility.ts` 白名单 |
| 权限 | `server/app/core/permissions.py` 和角色管理中的实际权限赋予逻辑 |
| 验证 | `server/tests/test_admin_creative.py`，使用独立临时数据库 |

新表按现有 `Base.metadata.create_all` 约定创建，确保模型启动前已导入；旧表确需补列时再走 `db_compat.py`。首期不修改内容发布包表。

### 7.2 数据模型

| 表 | 主要字段与约束 |
|---|---|
| `creative_ideas` | id、title、original_text、description、idea_type、status、priority、starred、parent_id、自身负责人/创建者、visibility、next_action、planned_at、review_at、conclusion、version、各时间及 archived_at/deleted_at |
| `creative_tags` | id、owner_id、name、normalized_name；同一所有者内规范化名称唯一 |
| `creative_idea_tags` | idea_id + tag_id 联合唯一 |
| `creative_materials` | id、kind、title、source_name、author、url、excerpt、insight、locator、引用对象类型/ID、owner_id、visibility、version、时间及 deleted_at |
| `creative_attachments` | id、material_id、storage_key、original_name、mime、size、checksum、uploader_id、时间；存储键不可由客户端指定 |
| `creative_idea_materials` | idea_id + material_id 唯一、关联启发说明、sort_order |
| `creative_idea_relations` | 左右 idea_id、relation_type；普通关联按 ID 排序后唯一，禁止自关联 |
| `creative_practices` | id、idea_id、type、title、occurred_at、action、expectation、result、decision、next_action、minutes、cost、metrics_json、result_links_json、creator_id、version、时间及 deleted_at |
| `creative_practice_materials` | practice_id + material_id 联合唯一 |
| `creative_events` | idea_id/物料 ID、操作者、event_type、前后变更摘要、request_id、created_at；事件追加写入 |
| `creative_capture_requests` | admin_id + idempotency_key 唯一、payload_hash、idea_id、created_at；同键不同内容返回冲突 |

负责人和创建者引用现有管理员主键，类型与现有账号模型保持一致；删除管理员时保留历史身份快照。文本主干用普通列；只有可变指标与结果链接使用受 Schema 校验的 JSON，不把检索字段塞进 JSON。

索引：负责人+状态+删除时间、父级、计划/复盘日期、最近实践时间、更新时间、物料创建者。首期采用分页 LIKE 搜索，限制关键词长度并转义通配符；按实际数据规模和响应表现再决定 FTS，不提前引入搜索服务。

### 7.3 接口草案

前缀 `/admin/creative`，沿用管理端现有响应封装和字段命名约定。以下描述资源语义，开发时核对客户端契约。

| 方法/路径 | 用途 |
|---|---|

### 7.4 权限与一致性

建议新增 `creative:read`、`creative:write`、`creative:manage`。read 可查看自己的与已共享数据；write 可创建并修改自己拥有的数据；manage 可管理共享数据与共享项负责人，但不因此查看别人的私人创意。超级管理员的特殊处理必须显式定义并审计，不照搬接口中的隐式绕过。

默认仅超级管理员具备模块权限，其他角色由管理员显式分配；即便默认 viewer/editor 拥有其他模块权限，也不自动获得私人创意权限。若沿用系统超级管理员全权限机制，则其访问私人数据的能力必须在界面说明。

所有查询与导出都做对象级鉴权；修改实践、关联物料、父级变更同时校验关联对象。共享子项的标题、数量和父级路径不得泄露私有对象；首期要求父子可见范围一致，调整范围需要显式列出受影响项。跨所有者建立父子关系首期禁止；普通关联按两端各自权限过滤。

写入使用数据库事务：状态+事件、实践+下一步、关联双方一致提交。`version` 通过带版本条件的 UPDATE 原子递增；冲突返回 409，前端保留本地输入并提供重新加载。创建幂等键与创意在同一事务写入。

删除创意前明确提示子项；首期有未删除子项时禁止删除父项，先移动或删除子项。删除不级联删除共享物料。回收站首期不提供物理删除或自动清理，后续制定保留策略再实现。

### 7.5 文件、链接与运行成本

私人物料不能直接放到公开静态上传目录后暴露 URL。新增鉴权下载接口，文件存私有数据卷子目录，文件名使用服务端生成存储键；路径做归一化检查。文件与数据库一起备份，恢复时核对关联。

首期建议允许 JPG/PNG/WebP/PDF/TXT/MD/DOCX，每文件不超过 20MB、每物料最多 10 个附件；服务端按实际文件特征与 MIME/扩展名交叉校验，对不匹配文件拒绝接收。文档只提供下载，首期不解析、不执行、不解压；下载设置安全 Content-Disposition 和 nosniff。反向代理大小限制需与接口一致。上传失败清理临时文件，已落盘未关联文件提供受控清理方案。

URL 仅接受 http/https，外链打开使用安全属性；Markdown 渲染禁用原始 HTML 或做白名单清洗。首期不由服务端抓取外链，避免平台依赖；以后增加抓取必须单独处理内网地址与重定向检查。

首期不增加模型调用、爬虫、向量库或队列，新功能不需要新的第三方密钥。部署继续用本地构建脚本，不在轻量云主机直接 compose --build。发布前核对私有附件卷、备份与 Nginx 限制，不需要构建或同步小程序包。

## 8. 首期范围、后续迭代与实施顺序

### 首期必须交付

快速记录；创意增改查、标签/收藏/筛选；父子与普通关联；状态流转；列表/卡片/基础看板；参考物料与受保护附件；实践及下一步；工作台到期视图；归档、回收站、单条导出；对象权限、变更审计与冲突处理；手机窄屏可用。

### 后续迭代

- 第二期：备忘录 TXT/Markdown/CSV 批量导入，先预览分条再确认，保留来源、幂等防重；独立下一步任务表、日历与通知；账号定位专用视图。
- 第三期：将成熟选题转为现有发布包，保留双向追溯；需要先评估现有模板是否支持原创选题，不能直接假设文章生成接口通用。
- 可选增强：AI 提炼标题、建议分类、相似创意提示、由原文拆选题、语音转写；用户主动触发、预览确认、保留原文，并接入已有模型用量记录。
- 独立评估：微信快捷收集、抖音指标自动同步、实时多人编辑、公开分享。这些需要额外渠道/授权或协作设计，不计入首期承诺。

### 开发拆分及预计投入

| 阶段 | 交付内容 | 粗估工作日 |
|---|---|---|
| 1 | 字段/交互定稿、数据库/权限/接口契约 | 1–2 |

## 9. 验收标准

1. 从快速记录打开到保存只需输入一次文本，不强制命名分类；刷新后记录存在，失败后输入不丢失。
2. 用两个业务示例走通方向、子选题、物料、实践、复盘；所有关系可回溯。
3. 私人数据不出现在其他管理员的列表、计数、搜索、引用提示、导出或附件下载中；无模块权限者所有接口均拒绝。
4. 实践中缺下一步、已沉淀缺结论均被服务端拒绝；状态和事件事务一致。
5. 重试快速记录不产生重复项；同键异内容、并发修改均能明确处理，不静默覆盖。
6. 自关联、父子循环、跨所有者父子和越权物料引用被阻止；软删除可恢复，物料不被误删。
7. 附件超限、伪造格式、路径穿越、未鉴权读取被拒绝；外链和 Markdown 无脚本执行。
8. 工作台到期规则在北京时间零点前后正确；分页和筛选范围内的计数一致。
9. 390px 手机宽度可完成快速录入、查看详情和追加实践；桌面可用键盘完成快速保存。
10. 管理端 `npm run build` 通过（包含 vue-tsc）；后端新增域测试及现有权限回归通过，使用独立临时库，不触碰生产数据。
11. 发布前同步操作手册、FEATURES、ARCHITECTURE 和权限/菜单说明；标明实际部署状态。首期未更改小程序，无须虚构客户端功能或修改各小程序 README。

建议内部试用目标：一周内随手记录十条真实想法、整理三条、实践一条并留下结论。衡量是否比备忘录更容易继续推进，再决定增加哪些能力。
