# 创意平台首轮代码审查与优化记录

日期：2026-10-22
结论：完成方案首期本地实现，并根据审查发现补齐可操作闭环。当前代码待用户验收，尚未部署生产。最终验证：创意域与系统权限回归共 3 项测试通过；管理端 `npm run build` 通过。

| 审查发现 | 优化处理 | 验证 |
|---|---|---|
| 快速记录幂等键若只放在事件日志，服务重启后无法安全复用 | 新增 `creative_capture_requests` 表，以管理员+幂等键唯一约束并校验内容摘要 | API 测试覆盖相同请求重放和同键异内容冲突 |
| 方案要求状态前置条件，但普通编辑不应绕过状态流转 | 状态单独走 transition API；服务端校验实践中的下一步、沉淀结论、搁置原因 | API 测试覆盖缺少下一步拒绝及合法实践闭环 |
| 父子结构必须保持可见边界 | 创建和编辑都校验父子权限范围一致，拒绝自关联与循环 | 创建父子 API 用例通过；服务逻辑检查循环 |
| 上传附件不可经公开 `/uploads` 暴露 | 私有随机存储键、大小/扩展名/MIME/关键签名校验、每物料 10 个上限、鉴权下载和软删除 | 测试覆盖上传、所有者读取及其他管理员拒绝 |
| 上传成功后界面没有附件入口，物料和关系不便撤销 | 物料列表/详情列出附件下载，补齐物料/实践/关系解除与回收站恢复入口 | 管理端类型检查与构建通过 |
| 归档项与导出无法从页面触达 | 增加归档筛选、恢复归档和 Markdown 导出 | 管理端构建通过 |
| 实践记录只增不改，与版本留痕要求不一致 | 增加版本校验的实践更新/软删除接口与编辑入口 | API 服务编译和域测试通过 |
| 到期计算依赖运行主机时区 | 使用项目北京时间 `utcnow()` 生成的本地业务时间 | 服务端以统一时区工具构建；跨午夜边界仍需验收环境复核 |
| 导出接口响应曾与管理端 Axios 包装契约不一致；标签、物料缺少完整维护和审计入口 | 导出统一使用 `ApiResponse`；增加标签增改删、物料详情/修订/事件、实践修订、附件移除，并把参考链接带入 Markdown | 测试校验导出数据与标签过滤；管理端 `vue-tsc` 与 Vite 构建通过 |
| 模块权限与共享数据编辑权限需要区分 | `creative:read/write/manage` 分层；读权限不能读取私人记录，管理权限只作用于共享记录；前端按对象可写标记显示操作 | 回归测试覆盖无模块权限拒绝、私人记录隔离及共享记录管理 |

## 尚待用户验收的边界

- 账号运营发布包没有现成的通用原创内容模板，故创意到发布包采用结果链接/物料记录衔接，未做自动转换。
- 当前上传是基本格式和签名校验，没有病毒扫描；文件以附件方式提供下载，不解压或解析 DOCX。
- 首期没有批量导入、自动抓取外站视频、AI 整理或抖音数据自动同步，这些在产品方案中列为后续。
- 其他角色默认没有创意权限；角色管理员可显式授予。共享创意只能读取，修改仍限创建者。
- 自动建表依赖服务启动正常导入模型；新表不会改动现有业务表。部署前要验证数据卷对 `data/creative-private/` 的持久化和备份。
