## 0. 排序原则

1. **文档先修**：文档漂移成本低、杠杆高——后续所有工作都依赖"文档可信"，先一次性收口（W1）。
2. **主线优先**：真题数据 → 出题引擎 → 运营物料是当前最活跃主线（W2/W3/W4），发布线（W5）卡在外部备案，尽早启动等待即可。
3. **外部依赖早启动**：ICP 备案、DeepSeek 换 key、2024 主卷 PDF 寻找——都是"等待型"事项，第一天就发起。
4. **质量债批量处理不阻塞主线**：lint warnings、弃用告警等固定批次集中清，不零敲碎打。

## 3. 依赖与风险

- **ICP 备案是全项目唯一硬等待**：不影响 W1-W4，但决定 W5 后半程与正式上线时间；建议本周发起。
- **人工教研审核是出题发布的关键路径**（3.3）：137 题积压越久，"审核→发布"闭环越难回补，建议阶段 1 就开始滚动审。
- **DeepSeek key 401** 同时阻塞 LLM 盲审（3.2）与每日出题线稳定性（4.3）——优先级高于其工作量所示。
- **2024 主卷 PDF 缺失**：若差异卷 PDF 不足以重建题干，2.2 将长期挂起，需尽早定性。
- **`.bak` 目录删除不可恢复**（git 未跟踪）：处置前必须确认对应数据操作已验收（D6a/D7/D8-D9 报告均在）。
- **数据隔离已知事实**：学习数据当前为账号级跨产品共享（launch-plan 已核实），孵化第三个产品前需重新决策。

- 出题：引擎脚本脱离 cron query 独立可跑；盲审报告补齐；137 题审核进度 > 50%。
- 发布：legal.ts 三处归零；服务器侧遗留项清零；备案处于"已提交待批"状态。
- 文档：本文件各事项完成后即时勾销；PROGRESS/DATA_STATUS/CHANGELOG 同步更新，不再出现"文档落后代码一周以上"。
