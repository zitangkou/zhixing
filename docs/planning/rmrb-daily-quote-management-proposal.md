# 人民日报后台收敛为每日金句管理：优化方案

日期：2026-10-13。状态：已部署提交`f641895`；旧档案备份清理完成，生产库已有36条待核对金句及72个仿写。生产LLM凭据待配置，配置后自动整理任务运行。

## 一、目标理解

人民日报菜单只保留一个子菜单“金句管理”。后台用于沉淀每天在申论物料工作区整理完成的金句：原句、出处、句式、用途、主题、仿写、高亮等属性可长期保存、检索和查看。

推荐以“每日金句档案”为核心：先把已经整理好的内容记录下来，再按需选出当天的精选合集。第一阶段重点是每日金句自动整理、录入、展示和管理；不恢复全量文章库、三刀解剖或自动发布与视频生成平台。

## 二、现状与问题

当前路由有6个子菜单：

| 子菜单 | 目前用途 | 建议 |
|---|---|---|
| 全量文章 | 文章档案、分类和AI评估 | 退出人民日报菜单 |
| 评论文章 | 评论正文和三刀解剖物料 | 退出人民日报菜单 |
| 客户端评论 / 金句 | 客户端文章采集、文章审核、金句提取审核 | 退出人民日报菜单 |
| 金句运营库 | 选句组稿、公众号/小红书初稿、发布登记 | 退出人民日报菜单 |
| 金句管理 | 已通过审核的金句列表 | 改造为唯一独立入口 |
| 采集批次 | 采集运行情况与补采 | 退出人民日报菜单 |

当前金句表`rmrb_comment_quotes`通过必填`comment_article_id`关联评论文章；仿写只有一个`application_example`字段。列表只返回金句审核通过的数据，通过评论文章和文章档案取得来源，展示、统计逻辑还关联运营包。

因此，现有页面不具备每日整理结果直接导入、多主题仿写编辑、句式骨架和关键词高亮管理。仅删除其他菜单无法满足目标。

依据：`server/admin-web/src/router/index.ts`、`views/rmrbArchive/QuoteLibrary.vue`、`server/app/models/rmrb_archive.py`、`server/app/services/rmrb_quote_ops_service.py`。

## 三、推荐页面形态

菜单结构：人民日报 → 金句管理。

一个主页面＋详情抽屉＋录入/编辑抽屉＋导入对话框即可，无须再拆新子菜单。

### 主页面

顶部默认今天，可切换日期或日期范围。显示真实统计：当天金句数、来源文章数、已精选数、仿写示例数；分页结果不能冒充全部筛选结果统计。

筛选：日期、关键词、主题、构件类型、精选状态、审核状态。搜索覆盖原句、来源标题、句式和仿写。

默认按“整理日期→来源文章→句子顺序”展示；可切换跨日期全库视图。

| 列 | 展示方式 |
|---|---|
| 金句 | 完整原句、关键词红色高亮、构件标签 |
| 主题与用途 | 原句主题、适用位置，不混淆仿写主题 |
| 仿写预览 | 默认第一条，显示“共2条”，点击详情看全部 |
| 来源 | 标题、刊发日、版次/栏目、原文链接 |
| 整理日期 | 独立于文章刊发日 |
| 精选 | 是否入选当天合集、顺序 |
| 操作 | 查看、编辑、复制、精选、归档 |

详情抽屉完整展示原句、句式骨架、好用之处、落笔指引、使用边界、多个仿写、来源证据和变更记录。每条仿写单独显示主题及红色高亮，明确标记“仿写示例，非原文”。

不因某条金句已发布就从知识库隐藏；金句作为长期素材仍可检索。使用记录与精选状态分开。

### 录入与编辑

支持直接录入单条金句、增加/删除仿写、指定高亮关键词；不要求管理员先到其他页面审核文章。

初始状态“待核对”，核对后“已确认”；确认动作只针对入库内容，不代表已发布。只录资料时无需上传公众号图文、视频。

### 批量导入

第一阶段提供JSON导入：上传文件或粘贴JSON→预览→显示新增/重复/异常→确认入库→返回结果。每日整理完成后由操作人员导入，先不绑定聊天自动写入生产库。

优先兼容现有：
- `金句汇编/金句复用数据.json`：10篇、30句、60个示例。
- 精选合集`素材/四句金句_原文与复用.json`：4句，每句2个主题仿写，附用途及高亮等信息。

对旧汇编中的`guidance`、`component`、`examples[].text`与精选文件中的`pitfall`、`kind`、`examples`二元数组做显式字段映射。预览展示转换结果，不假设两种JSON完全相同。

唯一金句建议按“标准化来源URL＋原句规范化指纹”去重；规范化仅用于指纹，保存和展示必须保持原句原样。重复导入默认跳过，补充属性需明确选择合并，不自动覆盖已确认内容。

## 四、数据设计

推荐独立金句实体，摆脱文章采集工作流的强依赖；旧表仅在有效金句迁移与核对期间临时保留，完成后按清理范围退役。来源与仿写分开建模，日期精选用关联表，不把同一句按每天重复存一份。

### 来源文章

标题、URL、媒体、刊发日期、真实版次、栏目、作者；不保存全文。每条金句独立保存对应的连续原文证据摘录，不能只保存文章级摘要。原档案ID可选，不能是必填前置。

### 金句

| 属性 | 说明 |
|---|---|
| ID、原句、原句类型 | 完整句/连续节选，不混入仿写 |
| 来源ID、证据/定位 | 原句及必要前后文的连续原文摘录、段落定位；用于逐字核对，不是AI概括 |
| 首次整理日期、句子序号 | 管理每日整理结果 |
| 构件类型、适用位置 | 开头点题/分论点标题/论证句/结尾升华等 |
| 原句主题标签 | 与仿写主题分开 |
| 结构公式 | 可替换槽位和逻辑关系 |
| 好用之处、落笔指引、使用边界 | 保留教学属性 |
| 高亮关键词 | 结构化数组，渲染时转义，不保存任意HTML |
| 核对状态、核对人、核对时间 | 草稿/已确认/归档 |
| 创建/修改时间、导入来源 | 维护和追踪 |

### 仿写示例（一句对多例）

主题、完整仿写、可选视频精简版、高亮关键词、适用位置、排序、核对状态。多个不同主题各存一条，避免把两段拼入同一字段。

### 每日精选与使用记录

“精选日期＋金句ID＋排序”表示当天选了哪几句，支持本次四句合集；不强制每天4句。可选使用记录保存平台、实际发布日期、标题、资源地址。第一阶段可仅实现精选，媒体附件/发布记录作为第二阶段增强。

每天每篇3句是内容整理规则，系统不应硬阻止短稿不足3句或用户选择其他数量的合集。

## 五、旧任务停止与无用数据退役（用户2026-10-13补充确认）

已确认：人民日报相关后台采集任务停止；旧模块数据不再继续使用，只考虑金句及支撑金句使用的必要属性。不是只隐藏菜单，也不长期保留全量采集档案。

### 停止任务

- 不再启动`server/app/main.py`中的人民日报采集调度任务。
- 停止电子报文章/版面采集、客户端评论发现、定时重试和补采。
- 停止采集后的全文获取、全文AI评估、文章分类、三刀解剖和金句自动提取等旧工作流任务；清理或取消待执行队列，运行中任务应可退出。
- 删除或禁用后台手动采集、重试、AI评估入口及对应触发接口，避免隐藏菜单后仍被调用。
- 实施时检查启动任务、服务内部循环、数据库队列，以及实际部署配置中的独立定时入口，防止遗漏。不得凭菜单变化宣称任务已停止。
- 新金句库新增独立的每日评论金句整理任务，另支持文件导入和人工维护；旧采集任务全部停用，不复用旧全量文章持久化流程。新任务只临时获取评论正文，处理后清理。

### 只迁移有用金句及必要来源

迁移范围为已采用/已确认、仍有使用价值的金句；不把旧草稿、被排除文章、未采用候选整体搬入新库。

迁移金句时先保存原句、主题、用途、原有仿写、核对记录；再从旧文章关联抽取标题、作者、刊发日、版次、栏目、URL和必要出处证据，写入独立来源记录。来源记录只服务已保留金句，不保留全报文章档案。

旧单仿写转为第一条示例，缺失属性标待补；旧发布日期或审核时间不得猜作整理日期。现有10月13日本地汇编按导入预览另行入库，其精选集合去重合并。

### 清理范围与顺序

1. 停止任务和触发接口，冻结旧模块写入。
2. 迁移有用金句及其必要来源、仿写属性；核对数量、引用和内容完整性。
3. 解除新金句库对旧评论文章、全量文章和运营包表的外键及查询依赖。
4. 清理旧文章档案、版面目录、采集批次、采集/评估队列与报告、文章排除规则、三刀稿、旧运营包及无用文件；旧金句表完成迁移后退役。已发布标记若仍有实际用途可转成金句的简要使用记录，不保留整套旧运营工作流。
5. 删除旧页面、路由、接口和专用服务中不再使用的实现；移除过期权限及专用配置。

清理前采用一次性可恢复备份作为实施回退措施，明确备份保存位置和期限；备份不作为新产品数据，也不继续采集。避免在金句仍依赖旧来源外键时直接删旧文章造成级联丢失。

边界：本次清理针对后台全量档案/评论采集/金句运营链路。学员端阅读、开采等独立业务表不因名称含“人民日报”而自动删除；若与后台旧表共享数据，应先列明实际关联并保留独立业务必要数据。内容参考库等页面对已退役后台档案的入口也应同步移除，不为旧采集数据继续保留展示功能。

## 六、接口、权限与实施范围

按现有域拆分约定，在独立服务中完成来源、金句、示例、导入、精选逻辑，保持模型/schema统一re-export。

拟新增接口能力：列表/日期统计、详情、新建/编辑、归档、导入预检与提交、导出JSON、每日精选维护。管理员读权限可复用`rmrb:read`；写入/导入/确认须检查现有写权限配置，明确后统一实现，不能仅以前端按钮隐藏控制写操作。

第一阶段：停止全部旧后台人民日报采集/AI任务、迁移有效金句、清理无用旧数据与功能；新建仅服务金句的每日自动整理任务；实现唯一菜单、每日列表与详情、单条编辑、多例仿写、JSON预检导入、去重、精选和权限。

第二阶段按需：公众号/小红书文件关联、发布记录、从本地整理流水线同步。第一阶段不新增站内自动生成短视频或自动发文功能。

## 七、验收案例

- 人民日报菜单只显示金句管理，旧5个入口不可继续使用旧编辑工作流。
- 导入2026-10-13汇编得到30句、60个仿写、10篇来源；再次导入不重复增句。
- 导入四句精选文件与全量库合并，标记4条当日精选，仍保持30句而非34句。
- 日期筛选、跨日检索、主题检索、分页和全量统计正确；刊发日期与整理日期可不同。
- 同一金句两个仿写主题分别展示，原句与仿写均可配置高亮。
- 编辑仿写不改原句；原句确认、来源回溯与变更记录明确。
- 旧后台人民日报采集/AI任务、重试和队列全部停止；新金句任务可独立运行，持久化结果仅含金句、证据摘录、必要来源及仿写；旧模块无用数据完成清理，独立学员端业务不受误删影响。

## 推荐结论

改造现有金句管理入口为独立每日素材库，支持整理结果直接导入及维护；用一句多仿写、日期精选和结构化高亮记录现有生产流程。停止全部旧后台人民日报采集与AI任务，旧工作流退出并退役；新建精简的每日金句整理任务。只迁移有用金句及必要来源、仿写和原文证据属性，其余旧模块数据按核对后的清单清理。


## 八、后台自动整理与原文保存边界（2026-10-13确认）

用户确认：保留每条金句对应的原文证据摘录，方便核对；全文只作临时处理，不沉淀全量文章库。

### 每日任务

北京时间定时运行（具体时刻实施时配置），发现当天评论及符合规则的手记→临时获取正文→AI每篇精选3句→程序逐字验证→生成句式、构件、用途、高亮及两个跨主题仿写→去重入库为待核对。无合格评论或不足3句如实记录，不凑数。失败按文章重试，已成功结果不重复写入。

任务管理放在金句管理页面顶部：今日状态、立即整理、重试失败项。只保存精简运行记录（日期、开始/结束、条数、失败URL及原因），不恢复“采集批次”菜单或全量文章数据模型。模型缺失、超时、内容无效时不假报成功；自动结果待人工核对，不自动标记精选或发布。

### 每条金句必须保存的证据

- 原句与包含它的连续原文摘录，必要时带前后句；来源标题、URL、日期、版次/栏目及作者。
- 原文位置（如段落序号）、完整句/句内节选标记、抓取时间。
- 原句与证据摘录的逐字核对结果；原文未包含原句时不得作为已确认金句入库。
- 原文高亮与仿写高亮分开保存；证据是原文，不是AI生成的概括。

证据范围以能判断原意为准，避免把整篇或大量段落塞进证据字段。引用出处不同或页面更新时不能静默替换已确认记录。

### 临时全文生命周期

优先在内存中解析、校验；确需临时文件时放任务临时目录，并设过期清理。正文处理完成、失败或取消后均清理；重试重新获取原文。

正文不写入文章档案表、业务附件、长期缓存、任务日志、错误报告或内容导出。运行日志只记录状态、URL和摘要化错误，不输出完整提示词中的全文。临时文件不得随部署备份长期保留；传给模型所涉及的外部服务留存取决于服务配置，不宣称后台清理等同于服务方删除。

人工详情页直接展示每条证据摘录与原文链接，核对通过后保留摘录，仍不要求存全文。新任务不会恢复旧文章采集/评估工作流。

### 补充验收

- 自动整理后，金句、每句证据摘录、两条仿写按天可查。
- 每条原句均能在保存的证据内逐字找到，节选标记准确。
- 重复运行不重复增句；部分失败可单独重试。
- 成功、失败、取消后的临时正文可清理，数据库、附件目录和业务日志无全文持久化。
- 旧任务已停，新任务运行入口与数据表明确独立。
