# 三刀精读公众号自动回复与用户增长体系设计方案

> 版本：v3.0  
> 日期：2026-09-07  
> 定位：三刀法解析人民日报评论 + 时政考点每日一练  
> 核心目标：**提高新关注激活率、7日/30日留存、内容消费深度、自然分享与渠道增长**  
> 适用阶段：个人订阅号 / 开发者模式逐步增强  
> 设计原则：先做到“好用”，再做到“上瘾但不打扰”，最后做到“可传播、可度量、可迭代”。

---

# 0. 最终结论

前面 DeepSeek、智谱、Kimi、豆包、千问几份方案的方向大体一致，但成熟度不同。

综合后，本公众号不应该被设计成一个“自动回复菜单”，而应该被设计成一个：

> **以“今日一练”为每日入口，以“三刀精读”为内容资产，以“学习进度”为留存抓手，以“题库检索”为工具价值，以“分享海报/渠道二维码”为增长入口的轻量公考学习终端。**

最终推荐的核心闭环：

```text
外部内容/视频/文章
      ↓
扫码关注公众号
      ↓
欢迎语：只推动一个首次动作
      ↓
「今日」5题体验
      ↓
完成 → 答案/解析
      ↓
记录学习进度
      ↓
连续学习 / 错题 / 专题推荐
      ↓
生成学习战绩卡
      ↓
用户自然分享
      ↓
新用户扫码进入
```

整个体系最重要的不是“回复多少内容”，而是：

1. 用户关注后 **10 秒内知道这个号有什么用**；
2. 用户 **30 秒内完成第一次互动**；
3. 用户第一次互动之后立刻得到结果反馈；
4. 用户第二天有明确理由回来；
5. 用户使用越久，沉淀的数据和内容越多；
6. 每个推广渠道都可以知道“用户从哪里来、留下没有”。

# 1. 对前面五份方案的综合判断

## 1.1 应当保留的设计

| 设计 | 是否保留 | 原因 |
|---|---|---|
| 数字导航 + 关键词双轨 | ✅ | 简单、稳定、低学习成本 |
| 「今日一练」作为核心入口 | ✅ | 最容易形成每日习惯 |
| 5题一组 | ✅ | 降低一次性阅读压力 |
| 答案后置 | ✅ | 形成完整学习动作 |
| 单题解析 | ✅ | 从“刷题工具”升级为“学习工具” |
| 题库关键词搜索 | ✅ | 越积累越有价值 |
| 连续学习数据 | ✅ | 给用户长期积累感 |
| 里程碑奖励 | ✅ | 适合早期冷启动 |
| 兜底先尝试搜索 | ✅ | 比单纯回复“菜单”体验好 |
| 用户生命周期 | ✅ | 后续做个性化的基础 |
| 渠道二维码/渠道标记 | ✅ | 推广必须可度量 |
| 战绩卡/学习海报 | ✅ | 自然传播优于硬裂变 |
| 加学习群 | ✅，但后置 | 新用户先体验价值，再引导入群 |
| 7天新人路径 | ✅，改造后 | 必须以“用户主动交互推进”为主 |

---

## 1.2 不建议直接照搬的设计

### ① 关注后强行连续推送 3 条

不作为默认方案。

原因：

- 原生公众号后台的关注回复能力有限；
- 多条连续欢迎消息容易造成刷屏；
- 是否可实现取决于账号权限、开发方式或第三方工具；
- 新粉阶段最重要的是完成第一次动作，而不是阅读三段说明书。

**替代方案：**

> 欢迎语只做“一次承诺 + 一个动作”。

更多功能在用户回复后再展开。

---

### ② 用户断卡后系统自动给他发消息

不作为个人订阅号第一阶段核心设计。

推荐改成：

```text
用户再次进入公众号
        ↓
系统读取 last_active_at
        ↓
发现已经 3 天没有学习
        ↓
当前这一次回复自动切换成「回归提示」
```

也就是说：

> **召回不是“主动追着用户”，而是“用户一回来，系统马上认出他”。**

以后账号权限、客服能力或其他触达渠道成熟后，再做真正的召回。

---

### ③ 强制“转发朋友圈领取资料”

不做。

原因：

- 用户体验差；
- 容易产生营销感；
- 存在平台诱导分享风险；
- 即使短期涨粉，也可能带来大量低质量粉丝。

替代方案：

> 做“值得分享的结果”，而不是“逼用户分享”。

例如：

- 我的连续学习 7 天战绩卡；
- 今日 20 题正确率；
- 本周薄弱考点 Top3；
- “我今天又比昨天多学了20分钟”的学习卡片。

---

### ④ 一开始就设置十几个功能入口

不推荐。

新用户只需要记住：

```text
今日
```

老用户再逐渐认识：

```text
精读
搜题
素材
我的
菜单
```

# 2. 优秀公众号回复体系值得借鉴什么

## 2.1 十点读书：价值说明 + 工具入口

公开历史案例中，十点读书的关注回复最值得借鉴的并不是具体文案，而是结构：

```text
先告诉用户：
关注我以后能得到什么

然后给：
往期内容 / 核心服务 / 产品入口

最后：
鼓励继续互动
```

### 对“三刀精读”的启示

不要第一句话就是：

> 回复 1、2、3、4、5、6……

而应该先回答：

> **“为什么值得留下？”**

---

## 2.2 罗辑思维：自动回复直接连接核心产品

历史公开案例中的罗辑思维并没有把自动回复做成百科全书，而是直接把用户送到最核心的内容和产品。

### 对我们的启示

公众号所有入口最终应该围绕三个核心资产：

```text
今日一练
三刀精读
学习进度
```

其他功能全部是辅助。

---

## 2.3 内容型公众号：欢迎语人格化

很多优秀内容号的第一句话具有明显的人格感。

这说明：

> 欢迎语不是“功能说明书”，也是品牌第一句台词。

“三刀精读”天然有品牌语言资产：

- 刀已磨好；
- 今天这一刀，先切观点；
- 第一刀：是什么；
- 第二刀：为什么；
- 第三刀：怎么办。

但要控制程度，避免为了“有个性”而显得油腻。

---

## 2.4 教育/工具类账号：用户不记菜单，只记需求

用户不会长期记住：

```text
31
32
41
42
```

用户真正会说的是：

```text
今天
人工智能
申论
新质生产力
错题
答案
```

所以成熟的回复体系应该从：

> “关键词表”

升级成：

> **“用户意图表”**

---

## 2.5 当前成熟运营的一条共识：欢迎语必须短

2026 年公开的公众号运营实践仍普遍建议：

```text
一句定位
+
一个价值
+
一个明确动作
```

而不是长篇欢迎词。

因此本方案采用：

> **单主行动 + 次级菜单召回**

# 3. 产品定位

## 3.1 公众号不是“文章订阅号”

最终定位：

> **一个每天 5～15 分钟即可完成一次学习闭环的公考政治理论学习终端。**

---

## 3.2 三个核心价值

### 价值 1：今天学什么

用户回复：

```text
今日
```

立即知道今天最值得学的内容。

---

### 价值 2：这篇文章怎么学

用户回复：

```text
精读
```

使用“三刀法”拆解人民日报评论：

```text
第一刀：是什么
第二刀：为什么
第三刀：怎么办
```

---

### 价值 3：我到底进步了没有

用户回复：

```text
我的
```

看到：

```text
连续学习
累计学习
完成题目
正确率
薄弱考点
本周进步
```

# 4. 用户生命周期设计

```text
新关注
  ↓
首次激活
  ↓
首次完成学习
  ↓
连续3天
  ↓
连续7天
  ↓
形成稳定学习习惯
  ↓
内容资产积累
  ↓
主动分享 / 加群 / 共创
```

---

## 4.1 新用户：0～1 天

目标不是让他“看懂所有功能”。

唯一目标：

> **完成第一次今日一练。**

成功指标：

```text
关注 → 回复「今日」
```

---

## 4.2 激活用户：2～7 天

目标：

> 让用户至少完成 3 次学习。

关键功能：

- 今日一练
- 答案解析
- 学习记录
- 三刀精读

---

## 4.3 习惯用户：8～30 天

目标：

> 让学习数据开始产生价值。

新增体验：

- 连续学习
- 薄弱点
- 错题
- 周报
- 专题推荐

---

## 4.4 核心用户：30 天以上

目标：

> 从内容消费者升级为社区成员。

可以开放：

- 共创题目；
- 推荐热点；
- 学习群；
- 榜单；
- 学习心得；
- 资料共建。

---

## 4.5 回归用户

系统判断：

```text
current_date - last_active_at >= 3 days
```

用户重新发消息时：

```text
好久不见。

你上次做到：
连续学习 7 天
累计完成 186 题

今天不用补很多，
回复「今日」先做 5 题找回状态。
```

避免：

> “你已经断卡3天！”

产品应该鼓励回来，而不是惩罚离开。

---

# 5. 最终欢迎语设计

## 5.1 推荐正式版

```text
刀已磨好，就等你了。

这里是「三刀精读」：
每天用人民日报评论拆观点、学申论，再做一组时政考点。

👉 回复「今日」
先做今天 5 道题。

其他功能随时回复「菜单」。
```

---

## 5.2 为什么不用“新人领取100条资料”作为第一动作

资料包的问题：

- 很多人领取以后不会再回来；
- 容易吸引“资料党”；
- 没有让用户体验真正产品价值。

而“今日5题”会立即让用户理解：

> 这个公众号到底是干什么的。

因此：

```text
第一次行动 = 今日5题
第二次奖励 = 新人资料
```

---

## 5.3 第一次完成5题后的回复

```text
第一组完成 ✅

你已经完成今天第一轮学习。

正确：4 / 5
用时：3分26秒

今天最容易错的是：
「新质生产力的核心内涵」

回复：
「解析」看这5题详细讲解
「继续」做下一组
「新人」领新人考点包
```

此时才发新人福利。

## 6.1 为什么主导航不再突出数字

数字可以保留兼容：

```text
1 = 今日
2 = 精读
3 = 搜题
4 = 素材
5 = 我的
6 = 加群
0 = 菜单
```

但 UI 文案优先展示自然语言。

原因：

> **人记“我要做什么”，比记“功能编号”容易。**

# 8. 今日一练：核心留存引擎

## 8.1 流程

```text
用户：今日

↓
系统读取当天题目
↓
推送第1组5题
↓
用户提交答案
↓
立即判分
↓
显示结果
↓
继续 / 解析
↓
完成20题
↓
生成今日学习记录
```

---

## 8.2 不推荐旧方案

旧方案：

```text
一次发5道完整长题
用户回复“下一组”
最后回复答案
```

可以作为 MVP。

但更推荐第二阶段升级为：

```text
逐题答题
→ 即时判分
→ 自动记录错题
```

---

## 8.3 完成后的黄金回复

```text
🎉 今日一练完成

20题
正确 16
正确率 80%

今天最需要再看：
① 新质生产力
② 共同富裕
③ 现代化产业体系

连续学习：7天 🔥

回复：
「错题」复习4道错题
「精读」看今天相关文章
「战绩」生成今天学习卡
```

注意：

> 完成以后不要再给用户 7 个选项。

最多 3 个。

# 9. 三刀精读

用户：

```text
精读
```

回复：

```text
📖 今日三刀精读

《文章标题》

第一刀｜是什么
核心观点：……

第二刀｜为什么
论证逻辑：……

第三刀｜怎么办
可提炼对策：……

申论可直接积累：
「……」

回复：
「全文」看完整拆解
「考题」做本文对应5题
「收藏」加入我的素材
```

形成：

```text
文章
↓
知识点
↓
题目
↓
错题
↓
素材
```

这是这个公众号最重要的差异化。

# 11. 兜底回复：绝不能只说“没找到”

```text

     ↓否

```

# 12. “我的学习”——真正的留存中心

不要再叫：

> 打卡中心

推荐改成：

> **我的学习**

因为用户真正关心的是进步，不是签到。

---

## 12.1 用户看到的数据

```text
📊 我的学习

连续学习：7天
累计学习：23天

本周：
完成 86 题
正确率 78%
精读 4 篇

薄弱考点：
① 经济
② 科技
③ 党建

距离下一个里程碑：
还差 3 天
```

---

## 12.2 “打卡”改成自动发生

推荐：

```text
完成今日第一组5题
= 今日有效学习
```

而不是：

```text
用户只发送“打卡”
= 打卡成功
```

这解决“伪打卡”。

# 14. 新人7天路径

不要依赖系统主动每天推消息。

采用：

> **状态机 + 用户主动推进**

---

```text

↓
今日5题
```

---

## D1

用户再次进入：

```text

```

```text

```

## D5～D6

根据前面数据做推荐：


# 24. 回复路由伪代码

```python
def handle_message(user, message):

    update_last_active(user)

    if is_returning_user(user):
        apply_return_context(user)

    intent = command_match(message)

    if intent:
        return dispatch(intent)

    intent = regex_match(message)

    if intent:
        return dispatch(intent)

    search_result = question_search(message)

    if search_result:
        return render_search(search_result)

    if looks_like_article_title(message):
        save_article_request(message)
        return render_article_received()

    intent = semantic_intent(message)

    if intent:
        return dispatch(intent)

    return fallback()
```

# 36. 公开调研说明

4. 本方案刻意不采用来源不明的“留存提升35%”“点击率提升58%”等行业百分比作为产品决策依据；真正效果应通过本账号 A/B 测试验证。
