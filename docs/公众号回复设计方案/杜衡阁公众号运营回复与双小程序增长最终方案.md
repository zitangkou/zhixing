# 杜衡阁公众号运营回复与双小程序增长最终方案

> 文档状态：最终推荐方案，当前仅作设计与后续实施依据，不执行公众号配置或编码。
>
> 版本：v1.0
>
> 日期：2026-09-07
>
> 适用范围：公众号“杜衡阁”、知行日知（时政学习）、知行策论（申论学习），以及小红书、知乎、微信视频号等外部内容渠道。

## 1. 最终决策

“杜衡阁”不再被设计成一个在聊天窗口里完成全部学习的“轻量题库”，而应当成为两个学习产品共同的内容中枢、可信入口和回访枢纽：

```text
外部内容触达
    ↓
杜衡阁关注／文章阅读／关键词回复
    ↓
明确推荐一个当期学习任务
    ↓
知行日知或知行策论完成阅读与练习
    ↓
保存进度、查看解析、继续学习
    ↓
公众号后续内容再次触达，或用户主动回来查找
```

三端各自只做最擅长的事：

| 载体 | 核心职责 | 不承担的职责 |
| --- | --- | --- |
| 杜衡阁公众号 | 长文解释、内容沉淀、品牌信任、双产品分流、关键词找入口 | 不在聊天里复刻完整答题器，不承担复杂学习状态 |
| 知行日知 | 时政文章、重点阅读、每辑 5 题、同文全文题目合集、长期重点专题、学习记录 | 不做跨科目套卷，不堆尚未开放的能力 |
| 知行策论 | 原文阅读、三刀示范、短练习、反馈与学习记录 | 不在首发期同时开放所有申论题型 |
| 小红书／知乎／视频号等 | 用单一知识点获取公域流量，建立内容认知 | 不承载完整学习闭环，不同时推广两个主任务 |

第一阶段只优化“内容看到后能顺畅开始一次有效学习”这一条主链路。免费资料、社群、海报和更多功能都必须服从这条链路，不能抢占首次操作。

## 2. 已确认的业务约束

1. 对外统一使用“时政学习”“申论学习”，产品名保持“知行日知”“知行策论”。运营文案避免不必要地突出敏感类别词，但不得改写真实来源标题、真题正式科目名称或隐瞒实际功能。
2. 一个公众号“杜衡阁”承接两个产品；已知公众号与小程序有关联基础，正式接入前仍需核对具体 AppID、主体、原始 ID 和可用接口权限。
3. 阅读和练习首期免费，不设置付费墙，不以分享或邀请换取核心内容。
4. 时政学习按每个平台每天 3～5 次规划内容触达；不是让用户每天必须完成 3～5 份任务。没有重大新内容时，使用“十五五规划”等长期重点专题作为可靠补位。
5. 申论学习先按每个工作日更新，成熟后再评估扩展到每日。
6. 时政用户可以只完成当期 5 题，也可以选择同一篇文章的全部题目合集；作答前可选择阅读全文或只看重点。
7. 产品保持“简单又深入”：首屏一个主任务，深入内容通过阅读—练习—解析—复习逐层展开；未稳定开放的入口直接隐藏。

## 3. 七份备选方案的综合取舍

本方案综合当前目录中的 DeepSeek、智谱、Kimi、豆包、千问、Gork 和 GPT 版本。候选稿中的平台能力与行业数字未逐项验证，不能直接作为实施事实；涉及公众号接口、消息窗口、二维码、菜单或小程序跳转的能力，统一以接入时后台实际权限为准。

| 候选设计 | 最终取舍 | 原因与改造 |
| --- | --- | --- |
| 短欢迎语、价值前置 | 保留 | 新关注用户先在一屏内看懂“能学什么、下一步做什么” |
| “今日”作为第一动作 | 保留并升级 | 回复后不在公众号粘贴长题，而是直达当期小程序任务 |
| 自然语言关键词 + 数字兼容 | 保留 | 主文案展示“今日、时政、申论、我的”，旧数字只作兼容，不要求用户背编号 |
| 五题一组、即时判分、完整解析 | 迁移到小程序 | 这是产品闭环，不适合在公众号消息中模拟页面状态 |
| 公众号内连续推送多组题 | 不采用 | 刷屏、状态易丢、内容难维护，并与已建小程序重复 |
| 三条分层欢迎消息 | 不作为默认 | 权限不确定且容易打扰；默认一条短回复，一个主按钮 |
| 打卡、错题、连续学习 | 保留产品价值 | 由小程序记录；公众号只提供“继续学习／我的学习”入口 |
| 自动沉默召回 | 暂不采用 | 不预设主动触达权限；用户再次互动时可识别为回归用户并友好承接 |
| 新人资料包作为首动作 | 后置 | 容易吸引只领取不学习的低质量用户；完成首次任务后再提供补充材料 |
| 战绩卡／学习卡 | P2 保留 | 分享真实学习结果，不伪造排名，不把核心内容与分享绑定 |
| 邀请好友解锁、朋友圈助力 | 不采用 | 用户质量低、营销感强，也存在诱导分享风险 |
| 题库全文模糊搜索 | 后置 | 第一阶段以已审核专题和当期入口为准；搜索要受内容状态和产品边界约束 |
| AI 自由问答 | 后置 | 先用确定性规则和已审核内容保证准确；AI 不进入首发关键链路 |
| 渠道二维码与 campaign 归因 | 必须保留 | 判断渠道质量、内容留存和后续投放的基础 |
| 虚构完成人数、全国排名、效果百分比 | 永不采用 | 只能展示真实可追溯数据；冷启动阶段直接展示用户自己的完成结果 |

## 4. 核心用户场景

### 4.1 新关注用户

用户从公众号文章、小红书、知乎、视频号或朋友分享而来。欢迎回复只需完成三件事：

1. 说明价值：每天把重要文章变成可读、可练、可复习的学习内容；
2. 给出当天最值得做的一件事；
3. 告知回复“菜单”可以查看其他入口。

目标不是“关注成功”，而是 24 小时内至少打开一次小程序并完成 5 题或一篇精读。

### 4.2 从时政内容进入

用户看到一个考点、易混项或五题预览后：

```text
帖子／公众号文章
→ 一个明确 CTA
→ 知行日知对应文章或对应分辑
→ 可先读全文／重点，也可直接练 5 题
→ 看解析
→ 可继续该文全部题目或回到长期专题
```

每篇内容只推广一个准确入口，不把“今日、长期专题、申论”三个码同时塞在尾部。

### 4.3 从申论内容进入

用户看到一个标题、规范表达、结构分析或仿写示例后：

```text
帖子／公众号文章
→ 知行策论对应示范
→ 读原文
→ 看三刀拆解
→ 完成一句／一段短练习
→ 查看参考与反馈
```

公众号负责讲清“为什么值得学”，小程序负责让用户亲手完成学习动作。

### 4.4 没有重大新时政内容

运营后台从已审核长期重点中选择内容，例如“十五五规划”专题：

```text
长期重点中的一个小切口
→ 新的讲解角度或易错辨析
→ 仍指向原专题内准确分辑
→ 文案明确为“重点复习／专题回顾”，不冒充当日新闻
```

### 4.5 回归用户

不责备断更，不强调“断卡损失”。用户再次发送消息时，如果已有可识别学习记录，回复：

```text
欢迎回来。你上次学习的是《……》，今天可以从这里继续。

【继续上次学习】
【做今日 5 题】
```

最多两个行动，优先恢复上下文。

### 4.6 链接失效、内容撤回或服务异常

公众号不能继续返回过期深链。统一降级顺序为：同一期有效入口 → 产品首页 → 简短故障说明。不得返回草稿、撤审文章或尚未开放页面。

## 5. 公众号信息架构

### 5.1 一级结构

用户真正需要记住的只有四个词：

| 意图 | 用户表达示例 | 回复目标 |
| --- | --- | --- |
| 今日 | 今日、今天学什么、做题、1 | 当前优先级最高的单一学习任务 |
| 时政 | 时政、长期重点、十五五、2 | 知行日知的今日入口和长期重点 |
| 申论 | 申论、三刀、精读、仿写、3 | 知行策论的最新示范和练习 |
| 菜单 | 菜单、帮助、导航、0、help、? | 展示精简导航和使用说明 |

“我的学习”在确认账号打通和稳定深链后加入；首发前不展示无效入口。“搜题、资料、社群、战绩”均不进入第一层。

### 5.2 推荐欢迎回复

```text
欢迎来到「杜衡阁」。

这里把重要文章整理成两种可完成的学习：
时政学习｜读重点、做 5 题、看解析
申论学习｜读原文、看三刀、练表达

👉 回复「今日」，开始今天最值得学的一项。
其他入口回复「菜单」。
```

如果账号能力允许可靠发送图文卡片，欢迎回复仍只配置一个主卡片；不追加三条功能说明。

### 5.3 推荐菜单回复

```text
杜衡阁 · 学习入口

「今日」今天先学什么
「时政」今日内容与长期重点
「申论」三刀精读与短练习
「我的」继续上次学习（开放后显示）

直接回复引号内关键词即可。
```

### 5.4 三类核心回复

“今日”回复：

```text
今日推荐｜{产品栏目}
《{内容标题}》
{一句话学习收益} · 约 {预计时长}

【开始今天的学习】
```

“时政”回复：

```text
时政学习

今日：{今日主题或“今日暂无新重点”}
长期重点：{当前运营置顶专题}

【做今日 5 题】
【查看长期重点】
```

“申论”回复：

```text
申论学习

本期精读：《{文章标题}》
重点练习：{本期训练目标}

【读原文并看三刀】
【直接练一句】
```

每次最多两个动作。按钮、图文卡片或文字链接采用哪一种，由实际账号权限决定；语义与落点保持一致。

### 5.5 兜底回复

```text
我暂时没找到对应入口。

你可以回复：
「今日」开始今天的学习
「时政」看今日与长期重点
「申论」看三刀精读
「菜单」查看全部入口
```

兜底不自动把任意用户文本当题库搜索词，也不承诺“已为你安排文章”。后续若增加搜索，只有命中已发布内容且置信度足够时才直接返回结果。

### 5.6 异常回复

```text
这个学习入口正在更新，暂时无法打开。
你可以先进入【{产品名}首页】，已完成的记录不会受影响。
```

异常信息应可由运营后台快速替换；不得静默跳到不相关内容。

## 6. 关键词与路由规则

按确定性从高到低匹配：

1. 系统命令和完全匹配核心词；
2. 核心词的明确别名；
3. 日期、专题代码等结构化表达；
4. 已发布内容标题或专题词检索；
5. 友好兜底。

第一阶段规则：

| 意图 | 全匹配优先词 | 可接受别名 | 禁止误配 |
| --- | --- | --- | --- |
| 今日 | 今日、1 | 今天、今天学什么、开始学习 | 不把所有“开始”都强行识别为今日 |
| 时政 | 时政、2 | 今日时政、长期重点、专题 | 原文标题中的普通词不能截断误配 |
| 申论 | 申论、3 | 三刀、精读、仿写 | “精读”命中后仍需落到已发布申论入口 |
| 菜单 | 菜单、0 | 帮助、导航、help、? | 问句中的数字不得触发功能 |
| 我的 | 我的 | 继续学习、学习记录 | 未上线时不注册关键词 |

所有规则需要版本号、启停状态、优先级、可用产品和兜底目标。运营人员能预览命中结果后再发布，避免一个词同时命中多个功能。

## 7. 内容运营与产品的共同发布单元

每次运营不应只保存一篇文案，而应保存一个“内容发布包”。一个发布包从同一份已审核母内容派生，至少包含：

```text
package_id
product_key                 # theory / shenlun
content_id                  # 母内容
entry_id                    # 小程序学习入口
campaign_key                # 本次运营活动
topic_type                  # daily / evergreen / review
official_account_keyword    # 公众号承接词
miniapp_path
h5_path
qr_scene
platform_variants
planned_at
review_status
published_refs
```

`campaign_key` 推荐采用：

```text
{产品}-{栏目}-{日期}-{主题短码}-{批次}
```

例如：

```text
theory-daily-20260907-15th-plan-a
shenlun-threecut-20260907-rmrb-a
```

### 7.1 同一母内容的渠道变体

| 渠道 | 内容任务 | 主 CTA |
| --- | --- | --- |
| 杜衡阁公众号文章 | 完整解释、来源、方法、部分示例、收藏价值 | 打开对应小程序学习单元 |
| 小红书 | 一条易错辨析／一组卡片／一个表达升级 | 扫码或按平台允许路径进入单一任务 |
| 知乎 | 回答真实问题，给完整推理与方法 | 阅读同主题完整学习单元 |
| 微信视频号 | 一个设问、一个辨析、一个依据、一个练习提示 | 通过账号允许的关联路径进入对应任务 |
| 抖音／B站（后续） | 短讲解或系统专题 | 仍使用同一 campaign，不另造教学答案 |

所有变体复用同一审核事实、答案和解析。平台文案可以重写，事实和教学结论不得分叉。

### 7.2 时政学习日常节奏

每天准备 3～5 个“传播切口”，不等于生产 3～5 篇互不相关母稿：

1. 当日重要内容总览；
2. 一组 5 题；
3. 一个高频易混点；
4. 原文重点表达；
5. 长期重点回顾或错因辨析。

每个平台分别排期，但要尊重实际发布与触达权限。公众号若无法按 3～5 次触达订阅者，允许发布为可访问文章、合并为一篇目录稿或将部分切口用于次日；必须记录“发布”和“群发触达”的差别，不能把素材生成量当成用户触达量。

### 7.3 申论学习日常节奏

首期每个工作日围绕一篇已审核内容产生：

1. 原文为什么值得读；
2. 三刀中的一个关键观察；
3. 一个表达替换或结构方法；
4. 一个可在小程序完成的短练习；
5. 周末复盘可复用本周已发布内容，不冒充新拆解。

### 7.4 公众号文章的承接位

每篇文章只保留一个主承接位，必要时文末增加一个次级入口：

```text
标题下：说明本篇能解决什么问题
正文中：给足独立阅读价值
文末主 CTA：进入同主题小程序学习单元
文末次 CTA：回复“时政”或“申论”查看同类内容
```

小程序码必须精确到内容或分辑；不能永远只扫到首页。码旁写明“扫码后会看到什么”，不写夸大收益。

## 8. 获客、激活与留存设计

### 8.1 北极星指标

推荐使用“公众号来源的每周有效学习用户数”。有效学习定义为满足其一：

- 知行日知完成至少一辑 5 题；
- 知行策论完成一篇三刀学习或一个短练习。

关注数、阅读量和扫码量是漏斗指标，不是最终价值。

### 8.2 核心漏斗

```text
内容曝光
→ 公众号关注／文章阅读
→ 回复关键词或点击承接位
→ 小程序有效打开
→ 首次学习完成
→ D1 再次学习
→ D7 有效留存
→ 自然分享或收藏
```

首期只盯五个数据：

1. 新关注后 24 小时内的有效入口触发率；
2. 入口打开成功率；
3. 首次 5 题／三刀学习完成率；
4. D1 再次有效学习率；
5. 不同渠道的 D7 有效学习留存。

### 8.3 渠道质量

每个二维码、链接和内容变体至少携带：

```text
channel
campaign
content_id
product
entry_id
```

分别记录小红书、知乎、视频号、公众号文章、公众号回复、朋友圈、社群和线下来源。后期投放依据 D7 有效留存和完成率，不只依据新增关注。

### 8.4 留存原则

- 学习完成由小程序自动记录，不让用户再回复“打卡”；
- 返回时优先继续上次进度，不制造断卡羞耻；
- 长期重点持续可见，降低内容对当天新闻的依赖；
- 完成后最多推荐三个下一步，默认两个；
- 资料包是学习后的补充，不是关注诱饵；
- P2 可生成真实战绩卡，但不显示未经验证的全国排名或虚构人数；
- 先证明用户愿意回来，再投入裂变、榜单和复杂激励。

## 9. 双产品与统一后端的配合

两个小程序保持独立前端、统一视觉语言和共用后端。公众号入口解析必须显式携带 `product_key`，防止同一内容串到另一个产品。

### 9.1 入口解析

推荐统一入口参数：

```text
product=theory|shenlun
entry={学习入口 ID}
section={可选分辑／练习 ID}
channel={渠道}
campaign={活动标识}
content={母内容 ID}
```

服务端完成：入口存在 → 产品一致 → 内容已发布 → 学习入口已开放 → 当前时间有效 → 返回目标路径。任一检查失败即走安全降级。

### 9.2 身份与记录

公众号 `openid`、小程序 `openid`、UnionID 或站内用户 ID 的可关联程度取决于主体与平台权限。首发设计不能假设一定能静默打通：

- 能可靠关联时，公众号回复“我的”可进入对应产品最近学习；
- 不能关联时，通过带参入口进入，小程序内部自行识别账号和本地记录；
- 未经用户授权，不把公众号行为与跨平台个人画像强行合并；
- 游客记录按现有登录同步策略处理，不能因扫码丢失。

### 9.3 功能开放策略

| 阶段 | 知行日知 | 知行策论 | 公众号显示 |
| --- | --- | --- | --- |
| 首发 | 文章／重点、5 题分辑、同文合集、长期重点 | 公共三刀示范、短练习 | 今日、时政、申论、菜单 |
| 稳定后 | 复习入口、错题、更多专题 | 更多三刀示范、表达积累 | 我的、继续学习 |
| 有留存证据后 | 薄弱点、学习报告 | 个人练习反馈、系列课程 | 战绩卡、周报 |
| 后续 | 其他细分题型独立产品 | 更多申论题型 | 按统一协议新增产品，不扩充首屏入口 |

## 10. 管理后台的最终能力边界

后续实现时，管理后台应提供以下能力，但本方案阶段不编码：

1. 回复模板：欢迎、菜单、核心意图、兜底、异常，可预览和版本回退；
2. 意图规则：关键词、优先级、别名、启停和冲突检测；
3. 入口绑定：回复模板绑定已发布的学习入口，而不是手填不可验证 URL；
4. 内容发布包：从审核母内容生成各渠道草稿、入口参数和物料清单；
5. 发布前检查：敏感表述、来源、答案、内容状态、深链、二维码、时间窗口和产品串线；
6. 渠道与活动：统一维护 campaign、二维码场景和平台变体；
7. 发布记录：记录平台稿件 URL、发布时间、是否实际触达、失败原因；
8. 数据漏斗：从内容、公众号到小程序完成的关键事件；
9. 紧急下线：撤回一个入口时，公众号回复和渠道链接同步降级；
10. 权限审计：内容审核、入口开放和公众号回复发布由不同状态控制。

第一阶段不做自动向外部平台发布；运营人员审核并手动发布，系统只生成草稿、入口和检查结果。

## 12. 分阶段实施路线

本节是后续排期，不代表立即执行。

### P0：把内容准确送到已开放产品

功能：

- 核验公众号与两个小程序的实际关联能力；
- 定稿一条欢迎语和四个核心意图；
- 内容发布包关联已发布学习入口；
- 生成可验证 H5 深链、小程序路径和渠道参数；
- 发布前自动检查草稿状态、入口状态、产品一致性、敏感表述和必填物料；
- 管理员手动发布，不做外部平台自动写入。

必要性：当前最大风险不是少一个互动玩法，而是内容发出后用户进不去、进错产品、看到未审核内容或无法完成学习。P0 先保证每次推广都真实可用。

验收：任一发布包能从母内容追溯到两个平台变体和唯一学习入口；入口失效时禁止导出；扫码／点击后抵达对应内容；后台无未开放功能宣传。

### P1：公众号成为稳定分流入口

功能：

- 接入实际可用的公众号消息能力；
- 确定性关键词路由、冲突检测、兜底和异常降级；
- 回复模板版本管理与预览；
- 渠道／campaign 归因；
- “今日”自动指向运营已选定内容，而非自动发布未经审核内容；
- 在能够安全关联身份后开放“我的／继续学习”。

必要性：当内容开始连续发布，人工替换链接很容易错配。P1 让入口可维护、可回退、可度量，同时不让公众号侵入小程序的学习职责。

验收：核心词命中唯一；草稿与撤审内容不可访问；两个产品不串线；所有回复落点可追溯；权限不足时能降级到静态后台配置。

### P2：基于真实行为增强留存和自然传播

功能：

- 回归用户继续上次学习；
- 小程序内真实学习周报和战绩卡；
- 已发布内容搜索；
- 按产品、渠道和栏目查看 D1／D7 留存；
- 仅在真实数据充分时展示群体统计；
- 社群入口经人工运营能力确认后再开放。

必要性：这些能力只有在首发闭环有稳定使用后才有价值。先用真实数据判断流失发生在哪里，再开发对应机制。

### P3：智能化与规模化

功能：

- 经人工审核的语义搜索和智能兜底；
- 内容变体辅助生成与一致性检查；
- A/B 测试、渠道预算和自动复盘；
- 新题型产品按统一入口与事件协议接入；
- 在权限、风控和人工复核成熟后评估半自动发布。

必要性：智能化应用于提效和检索，不替代内容审核，不让模型直接发布或编造事实。

## 13. 发布前检查清单

每个内容发布包必须全部通过：

- [ ] 对外名称使用“时政学习／申论学习”，产品名和实际落点一致；
- [ ] 母内容已审核，来源、日期、引用和答案可追溯；
- [ ] 小程序学习入口已发布，H5 路径可访问；
- [ ] 分辑、题目或三刀练习与推广文案完全对应；
- [ ] 同一帖子只有一个主 CTA；
- [ ] `channel/campaign/content/entry/product` 参数齐全；
- [ ] 小程序码场景值与目标页面一致；
- [ ] 不宣传尚未开放的“错题、AI、排行榜、付费、社群”等功能；
- [ ] 不含强制分享、助力解锁、虚构用户数、保证效果、伪造时效；
- [ ] 长期重点明确标注专题回顾，不伪装成当日新闻；
- [ ] 入口撤回时已有安全降级目标；
- [ ] 平台稿件经过人工预览，图片、字幕、题目和解析一致；
- [ ] 记录计划发布时间与实际发布／触达结果。

## 14. 需要在实施前确认的事项

以下事项不会阻碍当前小程序继续开发，但会阻碍公众号方案正式接入：

| 事项 | 推荐默认 | 为什么要确认 |
| --- | --- | --- |
| 杜衡阁账号类型、认证状态和接口权限 | 以公众号后台实际显示为准 | 决定菜单、回调、消息、二维码和小程序卡片能力 |
| 已关联的是哪个小程序 AppID | 分别记录知行日知／知行策论 | 防止双产品跳转串线 |
| 小程序正式名称、页面路径与提审版本 | 发布包只能选已登记目标 | 路径在开发版可用不代表线上可用 |
| 域名、HTTPS、ICP备案和业务域名 | 完成备案与平台配置后启用正式入口 | H5、回调和小程序网络请求均依赖真实环境 |
| 小程序码和带参二维码能力 | 先做路径协议，生成时再按权限落地 | 不预设个人主体一定拥有某种渠道能力 |
| 公众号一天可发布、群发、触达的真实限制 | 把“生成 3～5 个切口”和“触达 3～5 次”分别记录 | 防止运营目标建立在不可用权限上 |
| 用户身份关联方式 | 不能可靠关联时保持匿名渠道归因 | 涉及隐私、UnionID 条件和学习记录 |
| 反馈与人工服务方式 | 使用真实可达邮箱／公众号回复 | 异常、纠错和审核需要可联系渠道 |
| 首批正式母内容 | 各选 1 个当期内容和 1 个长期重点 | 用真实内容完成端到端验收 |

## 15. 明确不做的事项

- 不把公众号聊天窗口开发成第二套答题前端；
- 不做跨科目套卷；
- 不自动发布到外部平台；
- 不在未核验权限前承诺主动召回、连续消息、模板消息或特定二维码能力；
- 不强制分享、拉人或入群以获得答案和核心学习内容；
- 不伪造人数、排名、命中率、留存率和学习效果；
- 不开放空页面、建设中入口和没有稳定内容供给的栏目；
- 不让 AI 绕过事实、题目和运营审核直接面向用户发布；
- 不因为避免敏感词而歪曲来源或申报与实际功能不一致。

## 16. 最终验收标准

这套方案是否有效，不以“配置了多少关键词”判断，而以以下结果判断：

1. 新用户一屏内理解杜衡阁的价值，并能用一个动作开始学习；
2. 任一运营内容都能准确进入知行日知或知行策论的对应任务；
3. 用户在小程序完成学习，记录可保留，能自然继续；
4. 当日没有重要新内容时，长期重点仍能稳定承接；
5. 公众号同时服务两个产品但不混淆、不串码；
6. 每个渠道的关注、打开、完成和 D7 留存可追踪；
7. 内容撤审、入口过期或服务异常时不会暴露无效内容；
8. 首发体验保持简洁，深入价值来自内容和反馈，而不是功能堆积；
9. 后续新增其他细分题型时复用统一发布包、入口协议和事件体系，不破坏现有产品独立性。

## 17. 与当前开发计划的衔接

本方案完成后不立即编码公众号回复。小程序产品继续按既定开发单元推进：

1. U05：完成内容发布包、渠道入口和发布前检查，先解决“同一审核内容如何安全推广”；
2. U06：完成 H5 部署、小程序真机联调和提审材料收口；
3. 两个产品具备稳定正式入口后，再依据本方案启动公众号 P0／P1；
4. 每个开发单元执行“实现 → 验证 → 归档 → 独立提交并推送”，完成后自动进入下一单元。

这样能够避免公众号先宣传一个尚未稳定上线的入口，也能让后续回复配置直接使用真实、可验证的小程序页面。
