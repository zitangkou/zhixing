# 公众号自动回复体系完整设计方案

> 版本：v1.0・2026-09-07
> 适用：个人订阅号（未认证，开发者模式已开启）
> 内容定位：三刀法解析人民日报评论 + 时政考点每日一练



***

## 一、核心设计理念

个人号没有底部菜单，**用 "数字导航 + 关键词" 双轨制代替菜单**。参考得到 App、粉笔公考的交互逻辑，把公众号做成一个 "轻量学习终端"—— 用户发消息 = 点击菜单，回复内容 = 页面跳转。

### 留存的三个钩子



1. **每日必来**：每天有新题，答案后置制造悬念

2. **连续打卡**：天数可视化，断卡可惜心理

3. **进度积累**：题库 / 素材越攒越多，离开成本高

## 四、六大模式详细设计

### 模式 1：今日一练（刷题模式）— 核心留存功能

**触发关键词**：`1`、`今日`、`刷题`、`一练`

**交互流程**：



```
用户：1

公众号：

📝 今日考点一练｜2026-09-07

素材：《十五五规划纲要·开局产业科技数字》

价值分：97/100｜难度：中等偏上

📌 规则：题目分4组推送，每组5题。

做完一组回复「下一组」继续，

全部做完回复「答案」看解析。

—— 第1组（第1-5题）——

1\. 《纲要》回顾"十四五"时期成就指出，我国国内生产总值：

&#x20;  A.突破130万亿元  B.突破140万亿元

&#x20;  C.突破150万亿元  D.迈上140万亿斤台阶

...（共5题）

回复「下一组」继续 →
```



```
用户：下一组

公众号：—— 第2组（第6-10题）—— ...
```



```
用户：答案

公众号：

✅ 今日答案速查

1.B  2.C  3.A  4.D  5.B ...（共20题答案）

📖 详细解析回复对应题号，如「解析3」

💾 完整题目+解析长图：\[公众号文章链接]

🏆 完成今日一练！回复「打卡」记录学习
```

**关键设计点**：



* 答案后置（先做题再要答案），制造完成感

* 分组推送（5 题一组），避免一次刷屏

* 单题解析可查（回复 "解析 3"），支持深度学习

* 完成后引导打卡，形成行为闭环

## 六、留存机制总结



| 机制    | 心理学原理            | 实现方式            |
| ----- | ---------------- | --------------- |
| 每日新题  | 稀缺性 / 新鲜感        | 定时任务每天自动生成      |
| 答案后置  | 蔡格尼克效应（未完成事记忆更深） | 分组推送 + 回复「答案」解锁 |
| 连续打卡  | 损失厌恶（断卡可惜）       | 连续天数可视化展示       |
| 里程碑奖励 | 目标梯度 / 即时反馈      | 3/7/14/30 天分级奖励 |
| 题库积累  | 沉没成本（越用越舍不得走）    | 题库检索模式 + 历史沉淀   |
| 社群归属  | 社会认同 / 同伴压力      | 学习交流群           |
| 个性化数据 | 自我量化 / 进步感       | 打卡中心展示正确率和进度    |

## 八、技术实现路径

### 阶段 1：后台自动回复（本周可做，无需开发）

停用开发者模式后，用公众号后台关键词回复能实现：



* ✅ 被关注回复

* ✅ 主菜单导航（0-6 数字关键词）

* ✅ 固定内容回复（素材包、精读文章链接）

* ❌ 打卡天数记录（只能返回固定文字，无法持久化）

* ❌ 动态当日题目（无法自动读取云盘当日 JSON）

* ❌ 题库关键词搜索

**局限**：无法记录用户状态、无法动态返回当日题目、无法搜题。

### 阶段 2：开发者模式 + 后端实现（推荐，2-3 天开发）

在现有 FastAPI 后端加微信消息处理模块：



```
server/app/

&#x20; ├── api/

&#x20; │   └── wechat/              # 新增模块

&#x20; │       ├── routes.py        # 微信回调接口（GET验证 + POST消息）

&#x20; │       ├── handler.py       # 消息路由（关键词 → 功能模式）

&#x20; │       ├── modes/           # 六大模式处理器

&#x20; │       │   ├── daily\_quiz.py    # 今日一练（分组推送+答案解锁）

&#x20; │       │   ├── reading.py       # 三刀精读导航

&#x20; │       │   ├── library.py       # 题库检索（关键词匹配）

&#x20; │       │   ├── material.py      # 申论素材

&#x20; │       │   ├── checkin.py       # 打卡系统（天数/里程碑）

&#x20; │       │   └── community.py     # 加群引导

&#x20; │       └── session.py       # 用户会话状态（当前模式/第几组题）

&#x20; ├── models/

&#x20; │   └── wechat\_user.py       # 用户表（openid/打卡天数/累计/正确率）

&#x20; └── services/

&#x20;     └── question\_search.py   # 题库关键词搜索服务
```

**核心数据表**：



| 表名               | 字段                                                              | 用途               |
| ---------------- | --------------------------------------------------------------- | ---------------- |
| wechat\_users    | openid, nickname, checkin\_streak, total\_checkins, created\_at | 用户基本信息和打卡统计      |
| wechat\_sessions | openid, current\_mode, current\_group, last\_active             | 用户当前会话状态（做到第几组题） |
| checkin\_records | openid, date, completed\_quiz, correct\_count                   | 每日打卡明细           |

**动态能力**：



* 今日一练自动读取 iCloud 云盘当日题目 JSON

* 题库检索读取全部历史题目 JSON 做关键词匹配

* 打卡数据持久化，连续天数自动计算

* 用户做题进度记忆（做到第几组了，下次继续）

### 阶段 3：进阶功能（后续迭代）



* **答题判分**：用户发选项字母，自动判对错 + 返回解析

* **错题本**：自动收集用户答错的题，支持复习

* **个性化推荐**：根据薄弱考点推送相关题目

* **周 / 月学习报告**：自动生成学习数据总结

## 十、与现有自动化产能的对接

当前已有每日定时任务自动生成：



* 公众号 HTML（三刀法风格）

* 公众号超长图 + 4 张分段长图

## 十一、升级路径（何时需要企业号）



| 触发条件           | 为什么需要企业号        |
