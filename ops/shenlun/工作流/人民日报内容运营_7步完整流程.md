## 一、流程总览

本流程在「5步生产流程」基础上，新增「文章抓取」「自动筛选」「人工审核」前置环节，生图环节升级为 **Canva AI 风格预览 + ImageGen 成品图** 双通道，并在**每一步产出后设置人工审核门**，形成「产出 → 通知审核 → 通过则继续 / 驳回则优化重做」的闭环。

## 三、人工审核门机制（核心）

### 3.1 通用流程（每一步产出后）

```
步骤产出物料
    │
    ▼
发送审核通知（会话内展示 + 可选邮件通知）
    │
    ▼
◆ 人工审核（用户）
    │
    ├── 通过 → 物料标记 ✅已审核 → 进入下一步
    │
    └── 不通过 → 用户给出修改意见
            │
            ▼
    返回该步骤，按意见优化重做
            │
            ▼
    重新产出 → 重新提交审核（重新通知）
```

### 3.2 各步骤审核要点与通过标准

| 审核门 | 对应步骤 | 审核要点 | 通过标准 |
|--------|----------|----------|----------|
| 门1 | 抓取 | 文章是否完整无缺字；版次/栏目/日期标注是否正确；链接是否有效 | 全文完整、元信息正确 |
| 门2 | 初筛 | 打分是否合理；推荐理由是否贴切；排序是否符合直觉 | 排名与理由无明显错误 |
| 门3 | 解剖 | 两篇各自的总论点/分论点提炼是否准确；规范词释义是否白话；句式模板是否可套用 | 核心结构无偏差，模板可直接使用 |
| 门4 | 文案 | 两篇公众号HTML排版是否美观；小红书卡片是否独立可读；金句/案例是否准确 | 无错别字、无事实错误 |
| 门5 | 生图 | 文字是否准确清晰；配色风格是否符合平台规范（Canva 预览稿是否水印需清理）；画面是否达标 | 逐字核对无误，风格统一 |

### 3.3 驳回与优化规则

- 用户审核不通过时，需说明**驳回原因 + 修改方向**（如「文章A图3金句有错字，重生成」「分论点2论据与原文不符，调整」）
- 优化重做**只影响被驳回的文章/步骤及后续步骤**；已通过的步骤物料保持不变
- 同一物料允许多次驳回重做（最多建议3轮，超限则人工介入处理）
- 每次驳回与重做都要记录到 `物料/YYYY-MM-DD/审核记录.md`（时间、步骤、意见、处理结果），保证全程留痕

### 3.4 审核打回 → 模板维护（质量进化机制）

每次打回必须做**根因分析**，区分「模板要求不足」与「执行偏差」：

```
审核打回（驳回+原因）
  → 根因分析
    ├─ 模板不足 → 更新对应模板（版本+0.1，追加打回记录到模板维护日志）
    │            再按新模板重做物料
    └─ 执行偏差 → 按现有模板重做物料
  → 更新审核记录.md → 重新提交审核
```

- **模板要求不足**的判定：物料完全按模板执行但仍不达标（如「模板没规定封面字号」「模板没说明配色」）
- 模板更新统一在 `物料模板/物料模板总览与质量标准.md` 登记，且对应模板文件末尾「打回记录与维护日志」表追加一行
- 同类打回累积 ≥3 次 → 该检查项升级为模板内「质量自检清单」强制项
- 模板是质量基线：**先修模板，再重做物料**，避免同类问题反复打回

### 3.5 多智能体交叉审核（自动为主）

物料通过「规则自检脚本」后，模型**依次**以 4 个独立角色视角审查同一物料，各输出结构化问题清单，再汇总仲裁。角色定义详见 `物料模板/交叉审核角色定义.md`。

| 角色 | 审查重点 | 对应审核门 |
|------|----------|-----------|
| 教研审核员 | 论点提炼、论证方法、申论适用性 | 门3 |
| 事实核查员 | 原文引用、案例、规范词释义（逐字比对原文） | 门1/门3 |
| 视觉审核员 | 配色、字号、卡片结构、图片文字、Canva 预览稿水印 | 门4/门5 |
| 合规审核员 | 敏感表述、版权边界、夸张宣传词 | 门4 |

- **通过**：4 角色均无「高」严重度问题 → 自动进入下一步
- **需改**：存在「高」问题 → 按清单自动修复 → 复审
- **升级人工**：复审 3 次不通过 / 合规类高风险 → 转人工决策
- 交叉审核自动执行、不阻塞流程，问题清单与处理结果记入 `审核记录.md`

### 3.6 规则自检脚本（确定性拦截）

产出后先运行 `工作流/规则自检.py <物料目录>`，做**不依赖 AI 的硬校验**，拦截低级错误。脚本自动识别当日目录下**全部文章子目录**，逐篇校验：

| 校验项 | 规则 |
|--------|------|
| 原文命名/字段 | `<版次>_<栏目>_<标题>.md` + 标题/版次/栏目/日期/链接齐全（日级 原文/） |
| 文章子目录 | 至少存在 1 个 `<文章标题>/` 目录（当日入选 N 篇应 N 个） |
| 解剖完整性 | 摘录≤200字、规范词≥6、分论点2-4、语录≥2、动词≥4、句式≥3 |
| 公众号配色 | 中国红 #D0021B、无深蓝 #1F3864、8大区块齐全 |
| 公众号封面图 | 每篇 `公众号/封面图.png`（900×383，2.35:1，v2.16 本地底图版） |
| 小红书文案 | 6张卡齐全（封面A+5正文，v2.15）、无 Emoji |
| 小红书纯文本简化版 | 每篇 `小红书/<标题>_内容结构_简化版.txt`（≤1000字含空白） |
| Canva query | 若记录文件存在：≤220字、无色号、无 Emoji（v2.9 由「提示词≤150字」更新） |
| 图片文件 | 命名规范（01_封面A_*.png ~ 06_正文_5.png）；`小红书/图片/` 6 张（v2.15 单套 HTML 渲染） |

脚本 exit code 0 = 全部通过；非 0 = 存在需修复项，按报告逐项修正后再进入交叉审核。

### 3.7 状态文件（断点续跑 + 幂等）

每日物料目录下维护 `状态.json`，记录每步状态与审核门状态：

```json
{
  "date": "YYYY-MM-DD",
  "run_mode": "工作日自动化（7步SOP v2.16 全自动）",
  "selected_articles": ["文章A标题", "文章B标题"],
  "steps": {"step1_抓取": "done", "step2_筛选": "done", "step3_选文": "done",
            "文章A": {"step4_解剖": "done", "step5_文案": "done", "step6_生图": "done",
                      "step6.5_去水印": "done", "step7_自检": "done", "step8_审核": "done", "step9_归档": "done"},
            "文章B": {"step4_解剖": "pending", "step5_文案": "pending", "step6_生图": "pending",
                      "step6.5_去水印": "pending", "step7_自检": "pending", "step8_审核": "pending", "step9_归档": "pending"}},
  "review_gates": {"gate1": "passed", "gate2": "passed", "gate3_A": "pending", "gate3_B": "pending"}
}
```

- **断点续跑**：运行时先读状态文件，跳过 `done` 步骤，只补 `pending` 步骤
- **幂等**：重复运行不重复产出、不覆盖已通过物料
- 每步完成即更新状态（两篇文章各自独立标记），避免中断后从头再来

### 3.8 自动选文（每日 2 篇）

- 打分后，取总分 **前 2 名** 作为入选文章
- 两篇均 **≥21分（★★★）且第2名与第3名分差 ≥3分** → 自动选文，无需人工确认
- 否则 → 标记「需人工确认」，邮件通知用户从候选清单中指定（可指定任意两篇）
- 同分时优先「评论性强」（观点鲜明、贴近时事热点）的文章
- 选文结果（两篇）记录到 `筛选/确认结果.md`

### 3.9 人工角色降级（抽检 + 终审）

人工从「逐项审核」降级为：
- **抽检**：每天随机抽查 1 篇文章的物料核对交叉审核质量
- **终审**：交付前对合规类问题做最终确认
- **异常决策**：交叉审核 3 次不通过 / 选文分差过小 / 合规存疑时介入

### 3.10 automation 执行范围（v2.16 全自动）

- automation 在 06:30 单次运行，**一次性执行步骤1-9 全流程**（抓取→筛选→选文→解剖→文案→生图→自检→归档），无人值守、无人工审核卡点
- 选文后发通知告知（邮件+企微，不阻塞流程）；分差不达标时 README 标注「选文分差小，建议人工复核」
- 终审降级为「产出后通知用户抽检」，产出完成发通知（邮件+企微）附抽检提示
- 生成 `物料/YYYY-MM-DD/审核记录.md`，列出全部审核门状态与交叉审核问题清单（两篇分别列出）
- 用户反馈驳回时，由助手执行「驳回 → 优化重做」循环，直至全部通过
- 断点续跑：状态.json 每步完成即更新，异常中断后重跑只补 pending 步骤

### 步骤 1：自动抓取候选文章

**抓取范围：**
| 版次 | 版面 | 栏目 |
|------|------|------|
| 04版 | 要闻 | 【人民论坛】 |
| 05版 | 评论 | 【大家谈】【人民时评】【金台随笔】【评论员观察】及其他评论文章 |

**技术要点（电子版 URL 结构）：**
- 版面页：`http://paper.people.com.cn/rmrb/pc/layout/YYYY/MM/DD/node_04.html`、`node_05.html`
- 文章页：`http://paper.people.com.cn/rmrb/pc/content/YYYY/MM/DD/content_XXXXX.html`
- 从版面页解析所有 `<a href>` 链接，正文从 `id="ozoom"` 或 `<!--enpcontent-->` 标记提取，正则清理 HTML 标签
- 每篇保存为 md（标题、版次、栏目、日期、链接、正文）到 `物料/YYYY-MM-DD/原文/`

**异常处理：** 当天无评论版（周末/节假日/休刊）→ 记录并终止；单篇失败 → 跳过并记录。

**→ 审核门1**

### 步骤 1.5：原文 HTML 生成（2026-09-09 增补，批量）

对步骤 1 抓取的全部候选原文（`原文/` 目录全部 md）生成统一版式 HTML，并**归位到文章目录**（2026-09-09 用户定：每篇文章的原文与其他物料放一起）：

- **1.5a 候选池批量**：`python3 工作流/原文HTML生成.py --date <今日日期>` → 扫描 `物料/<今日日期>/原文/` 全部 `*.md`，逐篇生成同目录 `原文/<标题>_原文.html`
- **1.5b 文章归位**（选文后执行）：`python3 工作流/原文HTML生成.py --date <今日日期> --into-articles` → 选中文章的 md + `_原文.html` 复制/生成到 `物料/<今日日期>/<文章标题>/原文/`（与解剖/公众号/小红书/知乎同目录，文章自足成包）；匹配=解析标题（含降级）与文章目录名宽松匹配（忽略引号中英文/栏目括号后缀/零宽字符）；未选中文章留在日期级 `原文/` 候选池

## 七、使用注意事项

1. **审核闭环是质量保障核心**：每步必须人工确认通过后才进入下一步，杜绝「一次性跑完无人检查」
2. **驳回意见要具体**：反馈时说明原因+修改方向（注明是哪篇文章、哪张卡），便于精准优化
3. **物料全程留痕**：每步物料 + 审核记录归档，可追溯每次修改；两篇文章分别归档到各自目录
4. **图片文字准确性第一**：生图后逐字核对，错字立即重生成；Canva 预览稿水印需在发布前清理
5. **平台聚焦（v2.6）**：当前自动化只产出公众号 + 小红书；抖音恢复时启用 `物料模板/抖音卡片模版.md` 并按平台规则改造
6. **Canva 定位（v2.7）**：卡片图**全部由 Canva Pro generate-design 直出**（风格+主题元素+时令注入 query），下载最佳构图作成品；带「包含AI生成」水印的图需在 Canva 打开精修去水印或换构图
7. **先跑通再扩展**：先稳定运营小红书+公众号，抖音/双套风格按需恢复
