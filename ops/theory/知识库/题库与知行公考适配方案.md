# 题库（xingce-structured-data）× 知行公考 产品适配方案

> 版本：v1 · 2026-09-05
> 硬约束：**不改变知行公考现有产品结构**（不动旧模型/旧服务/现有页面路由，全部以增量方式接入）
> 调研基线：server/app/models/question_bank.py、api/admin/question_bank.py、services 清单、docs/architecture/question-bank-persistence-admin-design.md、src/pages/question/

---

## 1. 结论（TL;DR）

1. **两边模型天然契合**：产品端统一题库（`question_items/versions/papers/sections/positions/materials/import_batches` 七表）就是照着数据侧 schema v2 设计的（连 `topic/tag`、`provenance_json`、`quality_flags_json`、`source_key="guokao:2025:省级:1"` 都已预留）——**适配以"填充"为主，不需要改任何表结构**。
2. **真正的缺口是三段管线**：① 导入器未实现（admin 题库 API 目前只读）② 设计文档 §4.12 规划的 `collections` 集合框架未建表 ③ 学生端练习没有消费统一题库的入口。三者全部可以**增量新增**。
3. **顺序**：先数据补全（方案 §7 批次），导入器对着"已补全的数据"开发并试运行（2025 三卷是现成的种子集），训练功能按模块逐个上（第一模块=政治理论，已单独出详细方案）。
4. **发布期安全约束（2026-09，最高优先）**：知行公考小程序处于发布准备阶段——**一切触碰小程序 bundle（新增页面/改 app.config.ts）和线上环境（生产库迁移/部署）的工作一律冻结到发布完成之后**（详见 §10）。发布期内只做：数据侧批次（B0-B5）+ 服务端开发（独立分支+开发库），对线上与小程序零影响。

## 3. 字段映射表（schema v2 → qb 统一题库）

### 3.1 卷级

| schema v2（papers/*.json） | qb 表.字段 | 说明 |
|---|---|---|
| exam_year / paper_type | `qb_exam_papers.exam_year / paper_type` | 直接映射；`exam_kind` 固定"国考" |
| exam_name | `qb_exam_papers.title` | |
| schema_version | `qb_exam_papers.schema_version` | 存 "2" |
| total_questions | `qb_exam_papers.total_questions` | **存数据侧 actual_question_count**（2026=20 非官方 135），差异写 `source_document` 备注 |
| notes | `qb_exam_papers.source_document`（拼接） | |
| sections[].name | `qb_paper_sections.name` | 模块名原样 |
| modules[].number_range | `qb_paper_sections.number_start/number_end` | |
| sections[].materials[] | `qb_materials` + `qb_question_material_links` | `id`→`source_key`（规范见 §6）；`table_data`→`table_data_json` |

### 3.2 题级（核心：逻辑题 + 题位 两层）

| schema v2 question | qb 字段 | 适配规则 |
|---|---|---|
| stem / items / options / answer / explanation | `question_versions.stem / items_json / options_json / correct_answer_json / explanation` | 直接映射 |
| type（政治理论/选词填空/…） | `question_items.subtype` | qb 的 `module` 来自所属 section.name |
| topic / tag | `question_versions.topic / tag` | 词表同源（`_schema/topic-vocabulary.json`），导入时校验 |
| answer_source | `question_versions.answer_source` | 原样；**导入门禁按 §6.3 分级** |
| formulas / media | `formulas_json / media_json` | media 路径原样（相对 `xingce/`），静态挂载见 N7 |
| provenance{role,from_paper,…} | `qb_paper_question_positions.provenance_json` | 整体存 JSON |
| flags[] | `qb_paper_question_positions.quality_flags_json` | 高风险 flag 触发发布门禁（§6.3） |
| —（无） | `question_items.origin_type` | 真题固定 `real` |
| —（无） | `question_items.subject` | 固定"行测" |
| —（无） | `question_items.difficulty` | 数据侧无难度：默认 3；训练侧按答题数据回标（训练方案 §7） |
| —（无） | `question_items.response_type` | **全部 single**（组合/计数题的 options 本身就是组合结果/计数项），题型细分放 `analysis_payload_json`（见 §6.4），**不改 response_type 枚举** |
| material_ids | `qb_question_material_links` | 按 source_key 解析关联 |

**关键适配点——跨卷去重**：数据侧三卷共享的题是**三份拷贝**；qb 是"一题多题位"。导入器必须用 `canonical_hash`（stem+items+options 规范化哈希）把共享题归并为 1 个 `QuestionItem` + 3 个 `PaperQuestionPosition`（各自 source_key）。2025 三卷 395 题 → 实际逻辑题约 300 题上下，以 reconcile 端点核对。

## 10. 发布期安全策略（最高优先约束）

**背景**：小程序处于发布准备阶段，任何可能影响现网行为或小程序包体的变更都被视为风险。

### 10.1 风险分层

| 层 | 内容 | 发布期内 | 理由 |
|---|---|---|---|
| **绿（现在做）** | 数据批次 B0-B5（xingce-structured-data 仓库）；导入器/生成器代码编写（独立分支，不部署） | ✅ | 与小程序零接触：数据仓库是独立目录，不进小程序包、不进服务端运行时 |
| **黄（现在做，仅开发环境）** | 集合框架建表、qb 导入试运行、学生端 API 开发 | ⚠️ 仅 dev 库 | SQLite 迁移只在 `server/data` 开发副本演练；**不碰生产库、不做线上部署**（DEPLOY 流程冻结） |
| **红（发布完成后做）** | N6 新页面（`pages/question/bank/*` + `app.config.ts` 注册）、任何 admin/学生端路由注册合入主干、生产部署 | ❌ 冻结 | app.config.ts 变更 = 小程序包体变更；生产部署 = 现网行为变更 |

### 10.2 具体措施

1. **分支隔离**：全部服务端工作在独立分支（建议 `feat/qb-pipeline`）进行，主干在发布前只接受发布修复类提交
2. **数据库隔离**：开发用 `server/data` 副本（复制 zhixing.db/app.db 到 dev 文件），集合框架建表与导入演练全部指向 dev；生产库在发布前**零迁移**
3. **小程序 bundle 冻结**：不改 `src/app.config.ts`、不加 pages、不改 `AppTabBar.vue` 与现有页面组件；"真题库"入口的开发可以先以纯组件形式完成（不注册路由），发布后再一行接上
4. **admin 端点隔离**：新端点只在新文件中定义并挂独立 router，发布前不注册进 `api/admin/routes.py`
5. **验证方式**：每个黄层动作前后跑一次现有服务健康检查（本地起 server 冒烟：登录/今日页/练习页核心接口 200），确认零回归后才合并进 dev 分支
6. **回滚预案**：dev 库操作前快照（复制 db 文件）；一旦发现回归，弃用分支即可，主干与生产从未被触碰

### 10.3 发布后恢复顺序

发布上线且稳定运行一周后，按序解冻：N6 页面注册（含真机回归）→ 黄层内容合入主干并部署 → 按 §8 里程碑推进 M2-M5。

## 6. 导入协议（关键约定）

### 6.1 source_key 规范

- 题位：`guokao:{year}:{paper}:{number}`，如 `guokao:2026:shidi:7`（paper 取 shengji/shidi/xingzhengzhifa）
- 材料：沿用数据侧 `m{起}_{止}` → `guokao:{year}:m106_110`
- 逻辑题：`canonical_hash` 去重，无人工 key

### 6.2 幂等与批次

每次导入建一条 `ImportBatch`（source_path=数据仓库路径，source_hash=各卷文件内容哈希）。重跑时：hash 未变→整体 skip；单题内容变→新 `QuestionVersion`（version_no+1，change_summary 写来源），题位指向新版本。**答案字段更新不删旧版本**（版本快照不可变）。

### 6.3 答案分级门禁（对齐数据侧 answer_source）

| 级别 | answer_source | 真题卷模式 | 专项刷模式 |
|---|---|---|---|
| 绿 | `answer_book_*`（解析册）/ `xigua_zhihu_web_*` | 可用 | 可用 |
| 黄 | 双独立来源印证 | 可用 | 可用 |
| 橙 | `web_analysis_derived_*`（推导级） | 排除（或标灰显示） | 可用，答题页提示"答案待权威源复核" |
| 黑 | 未证实来源（如 B站键）/ null | 排除 | 仅题干练习不判分 |

### 6.4 训练维度标注（analysis_payload_json 规范）

```json
{
  "kind": "direct | combo | count",
  "distractor_tricks": {"A": "time", "B": "subject", "C": null, "D": "direction"},
  "confidence": "green | yellow | orange | black",
  "difficulty_hint": 3,
  "source_class": "B领导人讲话",
  "note": "仅当橙/黑时填写原因"
}
```

`kind` 判定规则：options 全为"N项"→count；options 含 ①②③ 组合→combo；其余→direct。`distractor_tricks` 首批由导入器按规则预填 + 人工校准（五手法词表见训练方案文档）。

## 9. 风险与开放问题

1. **B3（2020-2022 答案）是最大不确定项**——无解析册，网络答案键可信度低；建议决策：接受"仅答案、低置信标级"或补购解析册。
2. **跨卷去重的边界**：2024 市地/执法 125 题全部来自省级（题号偏移），canonical_hash 会把它们归并为一题多题位——这正好修正数据侧"重复题"展示，但要在 admin reconcile 报表里能看清归并关系。
